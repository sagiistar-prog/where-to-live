# 住哪儿 AI

住哪儿 AI 是一个面向中国大陆年轻人的 AI 居住决策助手。它不是房源平台，也不做房源分发，而是站在用户视角，对“去哪座城市工作、住哪个片区、租哪套房、签约前要核实什么、未来买房压力是否可承受”进行独立体检。

V1 以租房体检和决策计划为切口，因为它们高频、痛感强、天然适合截图和结构化输入；但产品底层已经按“择城、片区、房源、看房、付款、签约、入住、续租、退租、买房压力测试”的完整居住决策闭环设计。

## 产品定位

一句话：帮年轻人算清楚住哪儿才真的划算。

核心立场：

- 不卖房源，不替平台背书。
- 不爬取贝壳、链家、自如、安居客等租房平台数据。
- 只使用用户主动上传、用户手动输入、免费额度或开放数据。
- 不承诺房源真假或房价涨跌，只做风险提示、决策对比和核验清单。
- 目标不是生成漂亮报告，而是减少押金损失、错误通勤、烂合同、错误城市选择和买房现金流风险。

## 为什么是真需求

调研后确认，年轻人的居住决策痛点不是“缺少找房入口”，而是缺少一套能把机会、成本和风险放在一起比较的工具。

- 住房会影响定居城市选择，择城不是只看工资。
- 租房最大痛点是“很难找到适合自己的房子”，不是房源数量不够。
- 租金、面积、通勤、安全、配套、合同条款无法兼得，用户需要取舍解释。
- 通勤是隐形工作成本，会影响睡眠、运动、社交、加班承受力和长期状态。
- 合同、押金、维修、转租授权是真风险，能产生明确损失。
- 定金、意向金、服务费和押金常常发生在正式签约前，付款顺序错误会让用户立刻失去谈判位置。
- 买房痛点是月供压力、安全垫不足、生活质量下降和城市流动性损失。

## 当前原型范围

本项目当前是可运行的 Next.js V1 原型：核心页面已经成型，房源体检、截图字段识别、报告生成、合同审查、地图/天气增强、用量护栏和本地决策档案都走服务端路由；缺少 API Key、输入不足或额度接近阈值时会自动降级为本地规则和示例数据。

技术栈：

- Next.js App Router
- TypeScript
- Tailwind CSS
- shadcn ui 风格组件
- Framer Motion
- lucide-react

## 页面路径

- `/`：启动页，使用城市航拍循环视频建立沉浸感，展示产品定位、AI 报告预览、三大价值点、首访四步路径（画像、体检、价值账本、签前闭环），并提供类似 Vidu 的首屏决策输入框；用户可选择体检房源、被催付款、筛片区或排计划，输入一句当前情况后由 `/start` 抽取城市、租金、付款金额、工作地、预算、通勤上限、候选片区和阶段等关键信息，再预填进入对应工具。即使默认停留在“体检房源”，系统也会自动识别退押金、维修、交割、续租和首笔支出压力，直达 `/deposit`、`/repair`、`/handover`、`/renewal` 或 `/move`。
- `/auth`：登录注册页，邮箱/手机号 UI，点击后进入工作台。
- `/onboarding`：首访决策画像，1 分钟保存默认城市、工作地点、收入、预算、通勤上限、固定支出和居住偏好，后续 `/city`、`/area`、`/commute`、`/life` 和 `/analyze` 会自动复用。
- `/dashboard`：决策工作台，动态读取历史报告和工具回写，首页前置当前行动队列，展示最该先处理的 1-3 套房、付款/签约判断、最新决策计划、专项风险复核、下一步最佳动作、完成标准、停止线、本地决策价值账本、动态免费分析额度和最近分析。
- `/plan`：租房决策计划，输入当前阶段、时间压力、付款风险和证据状态，配置 OpenAI 后优先智能编排下一步任务，无 Key 或失败时自动回落到本地规则；顶部提供被催推进时的默认高风险处理路径，并生成可复制“今日行动包”、暂停线和完成标准；普通进入时会使用本地决策画像预填城市、收入、预算、通勤和偏好，从 `/case` 或工作台携带 `reportId` 进入时会改用同一套房源的城市、标题、租金、预算、通勤和报告结论预填，也可选择一套房源把计划写回居住决策档案。
- `/case`：居住决策档案，自动聚合历史报告，把每套候选房源转成签前闸门状态、通勤/生活半径复核、专项风险状态、证据缺口、数据缺口、付款/签约判断、签后生命周期、下一步最佳动作和后续动作顺序；如果入住现金流、交割、维修、续租或押金事件已经出现阻断/待补证，系统会优先处理这些真实损失点，而不是继续停留在签前清单；每套房都会生成行动包，把当前结论、今天只做的清单和可复制给出租方/中介的补材料、维修、交割、续租或押金文本整理出来；顶部会按阻断风险、低置信、付款/签约状态和签后争议风险排出当前行动队列；从报告页带 `reportId` 进入时会前置并高亮当前房源。
- `/city`：城市真实账本，自动带入画像里的默认城市、收入、预算、固定支出和通勤上限；从买房压力测试、报告或决策档案进入时，会优先合并 URL 中的城市、收入、租金/预算、固定支出、通勤上限和 `reportContext`，并显示来源提示；输入候选城市和税后月收入后，比较 offer、租金、生活成本、真实月成本和储蓄率，并输出达标税后收入、安全租金上限、谈薪差额和降租差额；如果携带 `reportId`，城市判断会写回同一份决策档案，并把城市、预算、安全租金上限和上下文继续带到片区初筛、房源体检和买房压力测试。
- `/area`：片区初筛，自动带入画像里的工作地点、通勤上限、预算和居住偏好；也支持从城市账本、买房压力测试或决策档案带入城市、预算、通勤上限和报告上下文；围绕通勤、生活半径、夜间动线和租金承受力筛片区，支持高德增强和本地规则降级，并生成“优先看 / 备选 / 暂缓”的本周看房队列和可复制片区看房排程包；携带 `reportId` 时会把优先看、备选、暂缓、第一片区和下一步动作写回同一份居住决策档案。
- `/commute`：通勤真实成本，自动带入画像里的城市、工作地、收入、预算和通勤上限；也支持从片区初筛、房源体检或决策档案带入同一套房源上下文；配置高德 Web 服务后优先估算公交/地铁路线、步行距离和换乘次数，失败或额度保护时回落到手动参数；折算晚归打车、坏天气和近通勤替代房租金差，携带 `reportId` 时会把结论写回居住决策档案，并在报告已触发通勤风险时参与付款/签约前判断。
- `/life`：生活半径审查，自动带入画像里的城市和居住偏好；也支持从片区初筛、房源体检或决策档案带入城市、房源和报告上下文；配置高德 Web 服务后优先查询周边超市、餐饮、药店、医疗、快递、运动和公园 POI，失败或额度保护时回落到手动参数；判断买菜、餐饮、药店、医疗、快递、运动、夜间照明和噪音是否适合长期居住，携带 `reportId` 时会把结论写回居住决策档案，并在报告已触发生活半径风险时参与付款/签约前判断。
- `/analyze`：房源体检，支持截图上传、截图字段识别、字段核对台、人工确认和手动输入；会自动带入设置页保存的城市、工作地、预算、通勤和偏好，也能接收片区初筛、城市账本、通勤成本、生活半径、买房压力或决策档案传入的房源标题、地址、租金、预算和 `reportContext`；页面会展示 OpenAI、地图、天气增强能力状态、生成前预计消耗和免费额度护栏；生成前会做信息充足度、数据降级和看房核实项预检。
- `/report/demo`：房源体检报告，展示综合结论、评分、真实月成本、通勤、生活半径、舒适度、签约风险和看房清单；报告新增“价值账本”，把隐藏月成本、月通勤时间、付款前暴露和押金争议风险折成用户能感知的钱和时间；历史报告会展示“报告可信度与降级说明”和“本报告的数据源与额度说明”，说明哪些结论高置信、哪些只能作为问题清单；真实历史报告会读取居住决策档案状态，在报告头部给出“现在先做什么”、完成标准、停止线和付款/签约闸门；报告首屏后提供上游取舍复核，把同一份报告上下文继续带入片区初筛、通勤真实成本和生活半径审查；报告中部提供“签前闭环”追踪，把通勤真实成本、生活半径、看房核验、官方核验、证据档案、付款闸门、签约风控，以及按风险触发的独居安全/合租边界闸门直接串起来；报告新增签前沟通包，把补材料、暂停付款、约晚上复看和合同条款确认转成可复制文本；报告侧栏支持复制或下载 Markdown 决策摘要，适合发给同住人、家人或带去看房现场，并遵守设置页的敏感信息隐藏开关。
- `/visit`：看房现场核验，按具体房源生成要测、要问、要拍和停签信号；支持从片区初筛自动带入看房队列、通勤、生活半径和停看规则，也支持从报告页自动带入通勤、生活半径、舒适度和合同风险；生成可复制现场核验包，结果页可把现场问题继续带入证据档案和付款闸门。
- `/safety`：独居安全审查，核验夜间路线、门禁楼道、低楼层、人际边界和隐私暴露；会优先带入画像偏好，也支持从报告页带入城市、房源和风险上下文；生成可复制独居安全核验包。
- `/shared`：合租边界审查，拆解室友作息、公共卫生、访客、费用、押金和转租授权；会优先带入画像偏好，也支持从报告页带入房源、租金和风险上下文，并生成可复制合租边界确认包。
- `/evidence`：租前证据档案，生成出租权、押金、维修、交割、聊天确认和付款备注的留证计划；支持从报告、决策计划、付款闸门、官方核验、看房核验、独居安全、合租边界、入住现金流和签后工具自动带入金额、授权、收款主体、退款、催付和风险上下文并生成证据包，勾选后会判断高优先级证据是否达到付款/签约前最低门槛，并可把缺证提醒继续带入付款闸门。
- `/official`：官方核验入口，整理住建、市场监管、政务服务等公开入口和签约前核验动作；每个核验任务会给出应保存证据和可复制询问话术，支持从报告、决策档案、付款闸门、签约风控、证据档案、看房核验、独居安全、合租边界、入住现金流、交割、维修、续租和押金回收带入城市、房源、合同状态、授权状态和风险担忧，并用高优先级官方核验硬门槛反写居住决策档案。
- `/payment`：付款前闸门，拦截定金、意向金、押金、服务费、收款主体和退款条件风险；支持从报告、官方核验、看房核验、证据档案、独居安全、合租边界、入住现金流、交割、维修、续租、押金回收和决策档案自动带入合同与付款上下文，并提供转账前硬闸门勾选确认和可复制暂停付款补证包。
- `/move`：入住现金流，测算押金、预付租金、中介费、搬家、添置和首月安全垫；支持从报告、决策档案、付款闸门、官方核验、证据档案、签约风控、交割、维修和押金回收带入城市、月租、首笔金额和现金流上下文，生成可复制现金流谈判包，结果可继续进入付款闸门、首笔证据档案、签约风控和入住交割。
- `/handover`：入住交割验收，确认钥匙门禁、表读数、家具家电、旧损坏和历史欠费；支持从报告、决策档案、入住现金流、付款闸门、官方核验、证据档案、维修和押金回收带入城市、房源、月租和风险上下文，生成可复制交割确认包，并继续进入证据档案、维修责任、交割确认闸门和押金回收。
- `/repair`：维修责任处理，判断漏水、发霉、家电故障、旧损坏和维修费用该如何留证处理；生成可复制维修责任通知包，结果可继续进入证据档案、维修垫付付款闸门、官方投诉/调解核验、押金回收和签约风控。
- `/renewal`：续租涨租决策，计算涨租幅度、替代房成本、搬家成本、押金风险和谈判底线；生成可复制续租谈判包，结果可继续进入续租协议审查、续租付款闸门、押金回收和多房源对比。
- `/deposit`：退租押金回收，拆解明确费用、争议扣款、返还期限、交割证据、沟通话术和可复制押金催退包；支持从交割、维修、续租、证据档案、付款闸门、官方核验和签约风控带入上下文，结果可继续进入证据档案、官方投诉/调解路径、扣款确认闸门和维修扣款拆解。
- `/compare`：多房源对比，按租金、真实月成本、通勤差额、报告可信度、风险和推荐排序横向比较，并给出省钱优先、通勤优先、签前安全、第一选择、备选、可否付款/签约、取舍解释、可复制对比决策备忘录和最需处理的下一步动作；从报告、档案或续租进入时会保留当前关注房源并在表格中高亮；只有 1 份真实报告时会先保留真实房源并补入示例替代方案，提醒用户继续体检真实备选，并提供低月成本、短通勤、低签约风险三种下一套真实候选体检模板。
- `/contract`：签约风控，展示合同条款识别入口、高频合同风险、签字前整改清单和可复制整改沟通包；支持从报告、付款闸门、官方核验、证据档案、合租边界、维修责任、续租决策和入住现金流带入上游风险底稿，但底稿只作为审查重点展示，不会自动填入合同文本；用户必须粘贴真实合同、费用说明、聊天记录或上传截图后才能审查。结果页可把合同风险继续带入证据档案和付款闸门。
- `/buy`：买房压力测试，输入收入、现金、目标总价、贷款和压力情景，计算月供收入比、安全垫和租售对比；支持从城市真实账本带入城市、收入、当前租金和固定支出，携带 `reportId` 时会把买房压力结论写回同一份决策档案。
- `/knowledge`：租房知识库，看房、合同、押金、独居安全、老小区、潮湿、通勤和官方核验；每条知识卡都会标注适用决策时机、建议核验来源和对应工具，页面顶部说明官方公开、免费额度、用户上传和本地规则的使用边界。
- `/settings`：个人设置，维护默认城市、工作地点、收入、预算、通勤、偏好、模型、数据源和隐私设置；本地保存后会影响下一次房源体检。

## 核心模块

### 1. 决策计划

用户输入当前所处阶段、决策窗口、付款压力、预算、证据状态和风险关注点，系统输出：

- 当前是否适合继续推进
- 必须先做、高优先级和可正常推进的任务
- 今日行动包、暂停线和做到什么才算完成
- 应进入的工具入口
- 证据清单和可复制沟通话术
- 暂停付款或签约的阻断项
- 配置 OpenAI 后，会基于本地规则基线做智能编排；无 Key、请求失败或输出不完整时，自动回落到本地规则，保证被催推进时也有可执行路径

### 1.1 下一步决策台

用户在工作台先选择当前阶段，系统直接给出：

- 当前该推进、暂停还是补证
- 高风险暂停条件
- 必须补齐的证据
- 下一步应进入的工具
- 看房前、看房后、被催付款、拿钥匙、入住后、续租退租、买房压力七个场景的动作顺序

### 1.2 居住生命周期总控

工作台新增一条从付款到退租的居住生命周期，把报告结论继续带入签约后的真实损失点：

- 付款前闸门：先看合同、授权、收款主体和退款条件，再决定是否付款。
- 入住现金流：把押金、预付租金、中介费、搬家和添置支出放进同一个安全垫测算。
- 入住交割：把钥匙门禁、表读数、旧损坏、家具家电和历史欠费固定成退租证据。
- 维修责任：先报修、留证、确认责任和费用边界，再决定是否垫付。
- 续租涨租：把涨租、替代房、搬家成本、押金风险和通勤变化一起算。
- 押金回收：拆分明确扣款和争议扣款，设置返还截止日和沟通底线。

### 2. 择城账本

用户输入目标城市、offer、税后收入和固定支出，系统比较：

- 房租收入比
- 真实月成本
- 储蓄率
- 通勤压力
- 城市机会密度
- 长期买房压力
- 可复制择城 Offer 决策备忘录，说明推荐城市、真实月成本、谈薪差额、降租底线和下一步动作

### 3. 片区初筛

围绕工作地点和生活偏好筛选片区：

- 通勤稳定性
- 租金区间
- 生活半径
- 夜间安全
- 老小区、低楼层、潮湿等风险
- 可复制片区看房排程包，把优先看、备选、暂缓、现场核验重点和停看规则整理成周末执行清单

### 4. 通勤真实成本

把“房租便宜但通勤很远”转成可比较的时间账：

- 每月通勤小时和年度折算天数
- 地铁公交、晚归打车等直接现金成本
- 按收入折算的时间机会成本
- 近通勤替代房最多值得多付多少租金
- 配置高德 Web 服务后优先读取公交/地铁路线，并展示本次路线依据和降级原因
- 高峰、雨天、末班车和晚归下车点核验清单

### 5. 生活半径审查

把“周边配套看着还行”转成可核验的长期日常判断：

- 买菜、餐饮、便利店和夜间补给
- 药店、社区医院和急诊路线
- 快递点、洗衣维修和日常杂事
- 健身、公园、散步和周末恢复
- 配置高德 Web 服务后优先读取周边 POI，并展示本次周边依据和降级原因
- 夜间照明、晚归路线、噪音、油烟和垃圾清运
- 现场实测清单、谈判杠杆和下一步动作

### 6. 房源体检

用户上传截图或手动输入房源信息，系统生成：

- 截图字段识别：租金、面积、楼层、地址、城市、费用说明和缺失字段
- 建议租 / 谨慎考虑 / 不建议租
- 总评分和分项评分
- 真实月成本
- 通勤分析
- 周边配套
- 生活半径与夜间可用性
- 买菜、医疗、快递、夜路和噪音的可选补充输入
- 天气与舒适度
- 合同风险
- 看房核验问题
- 下一步行动：生成看房核验、官方核验、证据档案、付款闸门和签约风控底稿
- 签前沟通包：补材料、暂停付款、约晚上复看和合同条款确认的可复制文本

### 7. 看房现场核验

把房源体检报告和用户偏好转成现场任务：

- 水压、排水、电路、门窗、采光、噪音
- 潮湿、霉斑、低楼层和老小区风险
- 报告带入的通勤、生活半径、夜间补给、快递、医疗和噪音短板
- 夜间最后一公里、门禁、楼道和消防
- 出租权、费用边界、家具家电交割
- 必须问清的问题、证据留存包、停签信号和可复制现场核验包

### 8. 独居安全审查

把“感觉不安全”拆成可执行核验：

- 夜间最后一公里实走
- 门禁、楼道、电梯和楼梯间
- 低楼层窗户、门锁和钥匙边界
- 快递外卖隐私暴露
- 室友、房东和维修上门边界
- 晚归、打车落点和物业响应

### 9. 合租边界审查

把“室友好不好相处”拆成可确认规则：

- 实际入住人数和公共空间边界
- 卫生间、厨房和冰箱分区
- 清洁轮值、访客过夜和安静时间
- 水电燃气、网费和公共用品分摊
- 个人押金、公共区扣款和提前退租责任
- 转租授权、签约主体和收款主体一致性
- 可复制合租边界确认包，用于把问题、条款、证据和暂停条件发给出租方、室友或中介确认

### 10. 租前证据档案

把“怕事后扯皮”前置到付款和签约前：

- 从报告带入授权、押金、维修、付款和交割风险
- 出租权和转租授权留证
- 押金、定金、租金付款备注
- 家具家电、墙面、管道、钥匙交割
- 维修责任和口头承诺文字化
- 聊天记录、合同版本、交割视频命名

### 11. 官方核验入口

把“查不到、不会查、不知道该问谁”变成签约前动作：

- 从报告带入出租权、备案、合同底线、公共服务和付款主体担忧
- 城市住房租赁合同网签备案入口
- 市场监管总局合同示范文本
- 住房租赁底线规则和非居住空间风险
- 出租权、授权链、收款主体核验
- 居住证、公积金、入学等公共服务材料影响
- 每个核验动作对应应保存证据：官方入口截图、权属/授权遮敏材料、合同条款对照、付款主体确认和聊天记录
- 每个核验动作提供可复制询问话术，用户可以直接发给出租方或中介补材料
- 高优先级官方核验硬门槛：出租权、备案路径、合同底线和付款主体未逐项确认前，不建议付款或签约
- 核验结果可继续生成证据档案和付款闸门，并可写回居住决策档案

### 12. 入住现金流

把签约当天的现金压力算清楚：

- 押金和预付租金
- 中介费、服务费和管理费
- 搬家、清洁、基础添置
- 水电燃气、宽带预存
- 到下一次发薪前的生活缓冲
- 可复制现金流谈判包：谈付款周期、服务费、中介费、收据和非必要添置延后
- 结果分流到付款闸门、证据档案和付款周期合同审查

### 13. 付款前闸门

把“先交钱锁房”拆成可验证的付款条件：

- 从报告带入租金、合同风险、授权风险、收款主体和退款条件担忧
- 定金、意向金、订金、押金、服务费和首笔租金
- 合同版本、出租授权、身份核验和收款主体一致性
- 退款条件、收据凭证、付款渠道和催付话术
- 付款阻断项、付款备注模板、暂停付款补证包和转账前硬闸门

### 14. 维修责任处理

把入住后的维修问题转成责任判断和处理计划：

- 漏水、发霉、家电故障、门锁失效、旧损坏和噪音扰民
- 自然损耗、设备老化、房屋质量和承租人人为损坏责任区分
- 报修证据、维修报价、费用垫付、报销确认和维修后复拍
- 押金扣款风险、可复制维修责任通知包和升级路径

### 15. 入住交割验收

把拿钥匙当天变成未来可用的证据起点：

- 钥匙、门禁、电梯卡、邮箱钥匙、燃气卡和换锁许可
- 水表、电表、燃气表、物业、宽带和历史欠费边界
- 全屋视频、旧损坏、清洁状态、家具家电和遥控器配件
- 可复制交割确认包、拍摄清单和退租对照依据

### 16. 续租涨租决策

把租期到期前的摇摆变成可计算选择：

- 当前租金、拟续租租金、同片区替代租金和税后收入
- 搬家费、中介费、押金损失风险和通勤变化
- 续租上限、搬家回本月数、可复制续租谈判包和补充协议清单
- 继续住、按涨价续租、搬去替代房三种成本对比

### 17. 退租押金回收

把退租时最容易损失的钱拆成可执行回收计划：

- 明确费用和争议扣款拆解
- 通知期和押金返还截止日
- 退租交割证据清单
- 扣款依据请求话术
- 谈判目标和底线
- 逾期未返还的下一步动作

### 18. 多房源对比

把候选房源放进同一套模型里，解释：

- 哪套综合更适合
- 哪套现金流压力更低
- 哪套通勤更稳定
- 哪套签约风险更高
- 哪套签前闸门已经闭环，哪套还不能付款或签约
- 这轮对比的月成本差距、通勤时间差、付款暴露和签前阻断项
- 如果选第一名，你实际放弃的是空间、通勤、现金流还是签约确定性
- 每个选择牺牲什么、换来什么
- 第一选择、备选、最需要处理的风险项和下一步动作
- 不足两份真实报告时，明确提示继续分析而不是伪装成真实对比

### 19. 签约风控

识别和提醒：

- 押金扣减条件
- 提前退租
- 维修责任
- 二房东授权
- 付款周期
- 家具家电交割
- 风险条款后续分流到证据档案和付款闸门

### 20. 买房压力测试

不预测房价，只判断买后能不能承受：

- 月供收入比
- 首付后现金安全垫
- 持有成本
- 通勤变化
- 降薪/失业压力
- 换城市流动性损失

## 数据源原则

所有外部数据源必须满足以下至少一种条件：

- 用户主动上传或输入。
- 免费额度的地图、天气、OCR 或模型能力。
- 政府、住建、市场监管、自然资源等公开入口。
- 非商用免费开放的信息或文章原文。

明确不做：

- 不爬取租房平台房源数据。
- 不绕过平台权限。
- 不读取用户私人账号、微信、邮箱、社交媒体，除非用户在当前任务中明确要求。
- 不将用户上传的敏感图片用于未经授权的训练或分发。

## 接口接入路线图

已接入到 V1 原型：

1. 文件上传：房源截图和合同截图仅由用户主动上传，当前走本地预览和服务端分析路由。
2. 视觉识别：配置 `OPENAI_API_KEY` 后，截图字段识别会抽取租金、面积、楼层、地址、城市和费用说明；无 Key 时降级为手动确认。
3. 大模型报告：配置 OpenAI 后生成结构化房源体检报告；失败、缺输入或无 Key 时生成本地规则报告。
4. 合同审查：配置 OpenAI 后审查用户主动粘贴或上传的合同内容；同时保留本地高频风险规则。
5. 决策计划：配置 OpenAI 后对当前阶段、时间压力、付款压力和证据状态做智能任务编排，并输出今日行动包、暂停线和完成标准；无 Key、失败或输出不完整时回落到本地规则。
6. 地图与天气增强：配置高德 Web 服务和和风天气后，报告生成会尝试补充地址解析、通勤、周边 POI 和天气舒适度；通勤真实成本页会优先读取高德公交/地铁路线，生活半径页会优先读取高德周边 POI；额度接近阈值时降级。
7. 决策档案：报告、城市账本、片区初筛、通勤真实成本、生活半径、买房压力测试、看房核验、官方核验、证据档案、付款闸门、签约风控、独居安全、合租边界和签后工具会把摘要写回本地档案。
8. 本地用量护栏：服务端累计高德和天气调用到 `.data/api-usage-events.json`，设置页、分析页和报告页会展示产品侧用量边界。

后续增强：

1. 用户系统：邮箱/手机号登录，保存偏好和历史报告。
2. 对象存储：房源截图、合同截图、聊天截图和交割照片只保存用户主动上传内容。
3. 通勤真实成本增强：继续细化工作日早晚高峰、末班车兜底、步行安全和晚归打车波动，不依赖租房平台数据。
4. 生活半径增强：继续细化 POI 的营业时间、夜间可用性、真实步行路线和噪音源现场校验，不依赖租房平台数据。
5. 官方开放数据：只接入免费额度、公开数据或需要用户主动确认的数据，不爬取租房平台。
6. 证据链存储：看房照片、交割清单、合同版本、付款备注和聊天记录备份由用户主动上传和导出。
7. 付费能力验证：单次深度报告、多房源对比包、签约前合同审查、城市/offer 决策报告、买房压力测试、决策计划、通勤真实成本、生活半径审查、独居安全审查、合租边界审查、付款前闸门、入住交割验收、维修责任处理、续租涨租决策和押金回收助手。

## API Key 配置

本地开发时，最省事的方式是启动 `npm run dev` 后进入 `/settings`，在“本地 API Key 输入”里填写 OpenAI、高德 Web服务、天气和 Resend Key；页面会写入根目录 `.env.local`，并同步到当前 dev server。

也可以手动编辑根目录 `.env.local`：

```bash
OPENAI_API_KEY=
AMAP_WEB_SERVICE_KEY=
QWEATHER_API_KEY=
RESEND_API_KEY=
RESEND_FROM_EMAIL=
AUTH_SECRET=
AUTH_GOOGLE_ID=
AUTH_GOOGLE_SECRET=
NEXTAUTH_URL=http://localhost:3000
```

Key 类型要这样选：

- `OPENAI_API_KEY`：OpenAI Platform 的服务端 Project API Key，只放在 `.env.local`。
- `AMAP_WEB_SERVICE_KEY`：高德开放平台选择“Web服务”，用于服务端地理编码、路线和周边搜索；不要把“Web端(JS API)”Key 当作这个变量。
- `QWEATHER_API_KEY`：天气接口服务端 Key，用于湿度、降雨、高温和空气质量判断。
- `RESEND_API_KEY`：Resend 服务端 Email API Key，用于邮箱验证码；发件地址可用 `RESEND_FROM_EMAIL` 配置。
- `AUTH_SECRET`：Auth.js/NextAuth 用于签名 session 的本地密钥，可用 `openssl rand -base64 32` 生成。
- `AUTH_GOOGLE_ID` / `AUTH_GOOGLE_SECRET`：Google Cloud Console OAuth Client 的客户端 ID 和密钥。若旧项目已有 `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`，当前代码也会兼容。
- `NEXTAUTH_URL`：本地开发填 `http://localhost:3000`，Google 回调地址配置为 `http://localhost:3000/api/auth/callback/google`。
- `NEXT_PUBLIC_AMAP_JS_KEY`：只有后续做前端地图展示时才需要，且必须在高德后台限制域名。

`.env.local` 已被 `.gitignore` 忽略，不会提交到仓库。完整说明见 [API Key 配置文档](./docs/api-setup.md)。

产品内 `/settings` 已加入“API 接入清单”“API 接入状态”和“免费 API 用量标识”：它只检查服务端环境变量是否存在，不会向 OpenAI、高德、天气或 Resend 服务发起探测请求，也不会消耗免费额度；用量标识读取 `.data/api-usage-events.json` 的本机服务端累计，没有调用记录时显示 0 次，不用示例数字冒充真实用量。`/analyze` 和报告页也会展示同一套 API Guardrail，让用户在生成前知道预计消耗，在生成后知道哪些数据源实时可用、哪些已经降级。

## 当前真实闭环

- `/plan` 已支持输入当前阶段、时间压力、付款压力、证据状态、预算、通勤和风险关注点，配置 OpenAI 后优先生成智能任务编排、阻断项、今日行动包和可跳转工具；无 Key、请求失败或输出不完整时，会自动回落到本地规则。普通进入会读取本地决策画像作为默认判断条件；携带 `reportId` 进入会读取最近报告并自动带入城市、候选房源、租金、预算、通勤和报告结论；用户也可以在最近报告选择器里选择是否把今日行动包以“决策计划”事件写回 `/case`。
- `/` 启动页已从单纯视觉首屏升级为首访决策路径：城市航拍视频下提供首屏决策输入框，用户可在“体检房源、被催付款、筛片区、排计划”之间切换，输入一句当前情况后由 `/start` 分流到 `/analyze`、`/payment`、`/area` 或 `/plan`；如果句子明显是退押金、维修垫付、入住交割、续租涨租或首笔支出压力，也会自动改道到 `/deposit`、`/repair`、`/handover`、`/renewal` 或 `/move`，并尽量预填城市、租金、付款/维修/扣款金额、工作地、预算、通勤上限、候选片区和阶段；右侧悬浮 AI 报告预览卡，底部保留通勤、配套、签约风险三大价值点，并把建画像、上传房源、查看价值账本、进入签前闸门串成首访路径。
- `/auth` 已接入 Auth.js/NextAuth Google OAuth，Google 登录是默认主入口；登录成功后会在本地 `.data/auth-users.json` 创建或更新用户记录并进入工作台，Google 返回 `email_verified=false` 或缺少邮箱时会阻止登录并在登录页显示清晰错误。原邮箱验证码流程保留为备用入口，Resend 为空也不会影响 Google 登录或项目启动。
- `/dashboard` 已升级为真实决策中枢，动态读取本地报告和工具回写，首页直接显示当前最该处理的候选房源、报告可信度、签前闭环进度、最新决策计划、专项风险复核、可否付款、可否签约、下一步最佳动作、完成标准和停止线；同时前置当前行动队列，按阻断风险、低置信字段、付款/签约状态和签后争议风险排出最该先处理的 1-3 套房，并显示已有多少套房源写回了决策计划；本地决策价值账本会把已保存报告里的隐藏月成本、月通勤时间、押金/付款暴露和工具回写进度汇总出来，并把工具写回拆成“少走弯路、少冒险付款、少留退租争议”三条价值轨道，展示最近写回的判断，但不把风险暴露包装成已省钱；免费分析额度也已从硬编码改为按本机本月已保存报告动态计算，用来表达可持续服务边界和付费价值；并新增居住生命周期总控，把付款、入住现金流、交割、维修、续租和押金回收串成证据链。
- `/onboarding` 已新增首访决策画像，登录页提供入口，工作台会在本地还没有偏好时提示完善；画像保存到浏览器本地，后续 `/city`、`/area`、`/commute`、`/life` 和 `/analyze` 会复用同一套默认城市、工作地、收入、预算、固定支出、通勤和偏好；桌面侧边栏和移动阶段菜单会同步展示当前画像摘要，未建立画像时直接引导补齐。
- `/case` 已升级为居住决策档案和签前闸门状态机，读取本地历史报告、报告可信度与工具回写结果，判断当前应暂停付款、补证推进，还是可进入签约前最后确认；顶部新增当前行动队列，按阻断风险、低置信字段、付款/签约状态和签后争议风险排出最该先处理的 1-3 套房；从报告页携带 `reportId` 进入时，会显示“当前报告已带入”的聚焦卡、把该房源排到列表第一位并高亮；每套房都会把触发风险的通勤真实成本、生活半径、独居安全和合租边界纳入付款/签约总控，并给出 `nextBestAction`，说明先做什么、为什么做、做到什么程度、未完成前不能做什么；当入住现金流、交割、维修、续租或押金写回阻断/待补证时，`nextBestAction` 会优先切到这些签后真实损失点；片区初筛也会进入下一步动作顺序，未完成且房源结果谨慎/不建议时会被标为本轮必补；行动包会按签前补材料、首笔支出、交割、维修、续租或押金场景生成不同可复制文本，继续追踪签约后的居住生命周期；现在也会显示从 `/plan` 写回的决策计划事件。
- `/city`、`/area`、`/commute`、`/life`、`/buy`、`/visit`、`/official`、`/evidence`、`/payment`、`/contract` 从报告或决策档案进入并生成结果后，会通过 `/api/case-events` 把摘要、状态和关键提醒写回居住决策档案；`/safety` 与 `/shared` 也会把独居安全和合租边界结论写回同一档案。若报告触发通勤、生活半径、独居、晚归、低楼层、合租、室友或转租等风险，它们会成为签前总控的一部分，未通过前不会显示可付款或可签约。其中官方核验必须是“硬门槛确认”事件通过，单纯生成核验计划只算待复核。
- `/city`、`/commute`、`/life`、`/buy`、`/visit`、`/safety`、`/shared`、`/evidence`、`/payment`、`/contract`、`/move`、`/handover`、`/repair`、`/renewal`、`/deposit` 的侧边或底部“继续下一步”入口已统一保留 `reportId`、城市、房源标题、租金/押金和压缩报告上下文；完整报告以 `reportId` 为准回看，不把长报告正文重复塞进每个 URL，避免用户从同一套房的决策档案里跳出去后丢失状态。
- `/plan` 已新增高风险默认路径，在用户被催付款或材料未齐时，先引导到房源体检、付款闸门、证据档案、官方核验和签约风控。
- `/city` 已从静态 Demo 升级为可输入候选城市、税后月收入、租金红线、固定支出和储蓄目标的本地测算流程，并会优先读取本地决策画像作为默认值；如果从买房压力测试、报告或决策档案进入，会把 URL 中的城市、收入、租金/预算、固定支出、通勤上限和报告上下文合并进表单，而不是回落到画像默认值；城市账本现在会把 offer 判断推进到底线层，输出为了达到目标储蓄率所需的税后收入、当前薪资差额、可承受最高租金、需要降租多少，以及“可进入片区 / 需要谈薪或降租 / 先别贸然换城”的行动判断；结果页新增可复制择城 Offer 决策备忘录，方便用户向同住人、家人或自己复盘说明推荐城市、真实月成本、谈薪差额、降租底线和下一步动作。若页面带有 `reportId`，城市账本会把推荐城市、真实月成本、安全租金上限和底线判断写回同一份居住决策档案，并把上下文继续传给 `/area`、`/analyze` 和 `/buy`。
- `/area` 已把片区初筛升级为看房队列、可复制排程包和决策档案回写：本地规则或高德增强后会按通勤、预算、生活半径、夜间动线和结构性风险，把候选片区拆成优先看、备选观察和暂缓看房，并为每个片区生成本周看房安排、现场核实重点、停看规则和可直接带去周末看房的文字包；携带 `reportId` 时会把片区结论写回同一份居住决策档案，减少无效看房。
- `/commute` 已支持输入单程通勤、步行、换乘、晚归打车、坏天气、收入、租金和近通勤替代房，生成通勤时间账、真实月成本和租金取舍建议，并会优先读取本地决策画像作为默认值；从片区初筛、房源体检或决策档案进入时会优先使用 URL 带入的城市、房源、工作地点、租金、通勤上限和上下文；配置高德 Web 服务后会先尝试实时公交/地铁路线增强，并在结果中展示路线依据、数据质量和降级原因；携带 `reportId` 时，结果会写回居住决策档案，若该房源报告已触发通勤风险，也会进入报告页与档案页的签前闸门，并继续分流到片区初筛、多房源对比或房源体检。
- `/life` 已支持输入买菜、餐饮、药店、医疗、快递、洗衣、运动、夜间照明和噪音源，生成生活半径评分、短板、夜间实测清单和谈判杠杆，并会优先读取本地决策画像作为默认值；从片区初筛、房源体检或决策档案进入时会优先使用 URL 带入的城市、房源和上下文；配置高德 Web 服务后会先尝试周边 POI 增强，并在结果中展示周边依据、数据质量和降级原因；携带 `reportId` 时，结果会写回居住决策档案，若该房源报告已触发生活半径风险，也会进入报告页与档案页的签前闸门，并继续分流到看房核验、片区初筛或房源体检。
- `/visit` 已支持从报告、片区初筛或决策档案带入房源、通勤、生活半径、夜路、噪音、潮湿、授权和押金风险，生成现场核验任务、勾选进度、停签信号和可复制现场核验包；核验包会把高优先级现场任务、必须问清的问题、证据留存和暂停定金/签约信号整理成能带去看房或发给中介确认的文本。
- `/safety` 已支持从报告或决策档案带入城市、房源、楼层、偏好和风险上下文，生成独居安全评分、夜间路线、门禁楼道、低楼层窗户、维修上门、快递外卖和隐私边界任务；结果页新增可复制独居安全核验包，把高风险项、夜间路线、钥匙换锁、维修上门和隐私边界整理成能发给出租方或中介确认的文本。
- `/analyze` 已从纯 mock 跳转升级为服务端分析提交流程，并支持把生活半径补充信息写入报告评分。
- `/analyze` 已新增截图字段识别和字段核对台：用户上传房源截图后可先调用 `/api/analyze/extract` 抽取租金、面积、楼层、地址、城市和费用说明，再看到每个关键字段是“截图识别、人工填写、待核对还是关键缺失”，确认后再生成报告；无 OpenAI Key 时明确降级为手动确认。
- `/analyze` 已新增生成前预检：在用户提交前提示关键字段缺口、OpenAI/地图/天气降级原因，以及独居、怕吵、怕潮、宠物、老小区等看房必须核实项，避免低置信报告被误当作签约依据。
- `/api/analyze/report` 会把生成前预检随报告一起保存，历史报告页会展示“报告可信度与降级说明”，并把预检结论写入 warnings 和导出 JSON；工作台和居住决策档案也会直接显示低置信待补证状态。
- `/analyze` 已读取设置页本地偏好，自动带入默认城市、工作地点、收入、预算、通勤上限、固定支出和居住偏好；页面会展示 OpenAI、高德和天气是否已配置、生成报告前预计会消耗哪些 API、以及高德和天气个人免费额度的产品侧累计，未配置或接近阈值时明确降级。
- `/analyze` 已支持 URL 上下文预填：从片区初筛、城市账本、通勤成本、生活半径、买房压力或决策档案进入时，会显示来源提示，并把 `source`、`sourceReportId`、`reportContext`、城市、工作地、预算、房源标题、地址和描述带入表单；提交后这些上下文会进入报告生成和本地历史档案。
- `/analyze` 生成报告后会把结果保存为本地居住决策档案，并跳转到对应 `/report/{id}`；报告页会立刻展示该房源的 `nextBestAction`、目的、完成标准、停止线和付款/签约闸门，进入 `/case` 时继续携带 `reportId` 聚焦同一套房，避免用户只看完报告却不知道下一步该做什么。
