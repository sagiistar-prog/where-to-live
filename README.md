住哪儿 AI 是一个居住决策工具，面向正在换城市、租房、看房、付款、签约或考虑买房的年轻用户。

产品不做房源分发，也不替代房源平台。它解决的是另一个问题：用户在做居住决策时，常常需要同时判断收入、房租、物价、通勤、片区、合同和付款风险，但这些信息通常分散在不同平台和聊天记录里，很难形成一次清晰判断。

## 当前定位

核心判断从生活成本开始，但不止于生活成本。

核心判断：

- 换城市前，先看税后收入是否覆盖真实月成本。
- 看片区前，先把通勤、生活半径和预算放到一起比较。
- 看房前，先整理房源信息、居住偏好和现场核验重点。
- 付款前，先确认合同、收款、退款和授权是否清楚。
- 买房前，先判断首付、月供和长期现金流是否可承受。

## 用户流程

用户可以从首页输入一句话开始，也可以直接进入对应工具。

主要入口：

- `房源体检`：输入房源信息或上传截图，生成租前判断和看房核验重点。
- `付款咨询`：输入担心的合同及其他法律风险，判断付款前应补齐哪些信息。
- `片区初筛`：比较通勤、生活半径、预算和片区适配度。
- `生活成本`：判断城市长期承受力和储蓄空间。
- `买房初判`：估算首付、月供、总价和长期现金流压力。
- `当前行动`：根据当前问题整理需要处理的事项。

## 页面结构

- `/`：启动页，使用全屏城市视频背景和一句话输入入口。
- `/auth`：邮箱注册和登录页，包含图形验证码与邮箱验证码流程。
- `/dashboard`：居住判断工作台，查看最近判断和当前行动。
- `/analyze`：房源体检。
- `/payment`：付款咨询。
- `/area`：片区初筛。
- `/city`：生活成本和买房初判。
- `/pricing`：方案与额度。
- `/report/latest`：最近一次房源体检报告。

废弃入口会重定向到当前主流程，避免用户进入已经移除的旧页面。

## 运行方式

当前唯一项目目录：

```text
<your-checkout>/where-to-live
```

安装依赖后运行：

```bash
npm run dev
```

开发服务默认启动在：

```text
http://127.0.0.1:3001
```

WSL 下进入项目：

```bash
cd "/mnt/i/Where to live"
```

项目位于 `/mnt/i` 时，直接在 WSL 上扫描 `node_modules` 会很慢。需要从 WSL 发起完整质量门时使用：

```bash
npm run verify:wsl
```

`verify:wsl` 会从 WSL 路径进入项目，并委托同一 I 盘目录下的 Windows Node/npm 执行质量门，避免 `/mnt/i` 上直接扫描依赖目录导致长时间卡住。

质量检查：

```bash
npm run lint
npm run build
```

运行态页面和一句话路由检查：

```bash
npm run smoke
```

`smoke` 默认检查 `http://127.0.0.1:3001`。如果本地服务未启动，脚本会自动启动 Next dev server，检查完成后自动关闭。检查已有服务时可以指定：

```bash
SMOKE_BASE_URL=http://127.0.0.1:3001 npm run smoke
```

PowerShell：

```powershell
$env:SMOKE_BASE_URL="http://127.0.0.1:3001"; npm run smoke
```

完整静态质量门：

```bash
npm run verify
```

独立生产运行态质量门：

```bash
npm run verify:prod
```

`verify:prod` 会先执行 `verify`，再用 `next start` 在随机空闲端口启动生产服务并运行同一套 `smoke`。它不依赖当前 dev server，也不会固定占用 `3100`，适合交付前或长时间代理结束前使用。

## 环境变量

本地环境变量放在项目根目录的 `.env.local`，不要提交到 Git。

邮箱验证码服务在服务端环境变量中配置，具体字段见内部开发文档。未配置邮件服务时，项目仍可作为本地原型运行。

## 当前状态

当前版本重点是让用户用最少输入完成居住判断：

- 首页保留全屏视频启动体验。
- 工具入口收敛为真实用户会用的几类判断。
- 旧内容和内部实现说明已从产品展示中移除。
- 方案与额度页面保留少量套餐，避免选择负担。
- 买房判断并入生活成本页，减少独立页面带来的流程冗余。
