# 住房知识库扩充与实际验收

2026-09-18。目标是帮助租客在看房、付款、签约和入住后找到适用于当地的核验依据。资料数量是覆盖记录，用户能否解决问题仍需任务试用验证。

## 从任务选择来源

| 用户要完成的事 | 收录内容 | 使用边界 |
|---|---|---|
| 看房时检查安全 | 高层消防、疏散通道、电动自行车、燃气热水器及通风 | 需要现场和专业检查，不能凭文字证明房屋安全 |
| 付款前看清费用 | 押金监管、中介服务清单与明码标价、合同范本 | 区分个人房东、租赁企业和经纪机构 |
| 搬入后办手续 | 广州与深圳网签备案、材料、公积金租房提取 | 自然人网签不等于所有企业业务；阶段比例不等于永久标准 |
| 寻找可负担房源 | 广州与深圳保租房条件、政府与社会房源差异 | 不提供实时空房库存，不推断个人已经取得资格 |
| 处理入住后问题 | 全国噪声法、上海具体装修时限、退租损耗案例 | 当地规则不能跨地区套用，个案不能保证自己的诉讼结果 |

来源从 18 扩充至 32 个：全国 9、北京 8、上海 4、广州 6、深圳 5。保留[目录](../knowledge/sources.json)、[原创简要整理](../knowledge/reference-notes.json)和[采集覆盖与哈希](knowledge-source-coverage.json)。全文快照与向量留在本地；仓库不打包第三方全文。可通过明确的公开来源清单重新采集。

## 核查中作出的取舍

- 排除已到期但在较晚时间转载的深圳旧政策，以及同一通知的政府镜像，避免把重复转载计成独立证据。
- 深圳普通租房提取 FAQ 的 80% 是阶段规则，截止 2027-10-31。到期后隐藏该问答，不将其当作永久比例；基础办法单独保留。
- 广州备案办事指引列三个工作日，地方规定对符合要求的材料要求当场办理。摘要并列说明并引导向受理部门核对，没有把二者合并成统一法定等待期。
- 广州保租房文件写“印发起有效三年”。目录记录推算的截止日及推算依据，而非伪装成页面明示日期。
- 深圳一处政府门户在本机 Python TLS 握手失败，改用经核验的同文住建局页面，保留证书验证。第二轮 32/32 采集成功。

## 可运行的数据链路

公开来源目录与 JSON Schema校验 → 正文及表格抽取 → Unicode清洗 → JSONL → 320字符切分、40字符重叠 → 真实BGE编码 → 独立索引 → 地区和有效期过滤 → 双路召回 → RRF → 带出处的证据。

实际 146,791 个清洗后字符生成 540 个片段。采用 FastEmbed 0.7.4、BAAI/bge-small-zh-v1.5、512维归一化向量；真实 tokenizer 检查最大 321 token，未超过 512 上限。模型内部处理 token 和位置表示，应用层使用句向量。没有用随机向量或哈希向量替代推理。

JSON路径采用 BM25+余弦相似度；PostgreSQL路径采用全文排名+pgvector，两路由 RRF 融合。二者词法排名不同，不互称同一个实现。来源日期和适用条件随片段保留；有效期和地区在排名前过滤，避免过期资料占满候选列表后才删除。

## 更新与复现

依照[运行说明](../knowledge/README.md)在全新目录采集、构建并启动服务。任一采集失败会留下失败记录及部分语料，并返回非零退出码；不会覆盖旧快照。完成采集后运行：

```sh
python knowledge/evaluate.py --index output/public-kb/index.json --cases knowledge/evaluation/expanded-cases.json --output output/evaluation/expanded-new.json --cache-dir .cache/models --min-hit-rate 0.9 --max-false-evidence-rate 0
```

当前开发集门槛只用于防止明显退化，不能证明法律正确性。上线前仍需独立标注，增加同义问法、政策冲突、失效资料、跨地区误用和证据段落相关性评估。周期性更新还需核对是否修订、废止或续期；重新抓取到页面不等于它仍有效。

此前带 `HOUSING_KB_URL` 的网页启动被自动审批拒绝，返回 `blocked by policy` 且无具体原因，本轮没有改道重试。默认网页与独立向量服务分别验收，完整网页到向量数据库的端到端验收仍有缺口。未进行律师审查、真实租客试用或线上客户效果验收。
