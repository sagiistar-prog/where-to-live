# API Key 配置

本项目的 API Key 统一放在根目录 `.env.local`。这个文件只在本机使用，已经被 `.gitignore` 忽略，不会提交到仓库。

## 你现在要填哪里

最简单的方式：启动 `npm run dev` 后进入 `/settings`，在“本地 API Key 输入”里填写 OpenAI、高德 Web服务、和风天气和 Resend Key。保存后会写入项目根目录 `.env.local`，并同步到当前 dev server 的服务端环境变量；页面不会回显真实密钥。

也可以手动编辑文件：

打开根目录的 `.env.local`，把等号后面填上自己的 key：

```bash
OPENAI_API_KEY=你的 OpenAI API Key
AMAP_WEB_SERVICE_KEY=你的高德 Web 服务 Key
QWEATHER_API_KEY=你的和风天气 Key
RESEND_API_KEY=你的 Resend API Key
RESEND_FROM_EMAIL=你的 Resend 发件地址
AUTH_SECRET=你的 Auth.js 本地 session 密钥
AUTH_GOOGLE_ID=你的 Google OAuth Client ID
AUTH_GOOGLE_SECRET=你的 Google OAuth Client Secret
NEXTAUTH_URL=http://localhost:3000
```

其中高德请选择“Web服务”平台，这个 Key 给 Next.js 服务端路由使用；你截图里的“Web端(JS API)”只适合将来在浏览器里展示地图组件，不能替代 `AMAP_WEB_SERVICE_KEY`。OpenAI 使用 OpenAI Platform 的 Project API Key，Resend 使用服务端 Email API Key，和天气 Key 一样都不要加 `NEXT_PUBLIC_` 前缀。

填完后重启开发服务：

```bash
npm run dev
```

启动后进入 `/settings`，可以看到四块配置反馈：

- “本地 API Key 输入”：把真实 Key 写入本机 `.env.local`，留空字段不覆盖已有配置，生产环境默认关闭写入能力。
- “API 接入清单”：确认每个 Key 应该在哪个平台创建、填到哪个环境变量、什么时候会消耗额度。
- “API 接入状态”：只检查服务端是否读取到环境变量，不会向第三方发起探测请求。
- “免费 API 用量标识”：展示高德和天气的产品侧累计次数，保护个人免费额度。

进入 `/analyze` 时，页面会复用同一套 API Guardrail：展示当前 Key 状态、生成前预计消耗、免费个人额度产品侧累计和会触发降级的条件。报告生成后，报告页会继续展示本报告的实时/降级数据源和后续工具的消耗边界。

## 安全原则

- 不要把真实 key 写进代码。
- 不要把真实 key 发给前端组件。
- 只有 `NEXT_PUBLIC_` 开头的变量会进入浏览器，密钥默认不要使用这个前缀。
- 如果后续使用 `NEXT_PUBLIC_AMAP_JS_KEY`，需要在高德后台限制域名。
- OpenAI、地图 Web 服务、天气、Resend 等接口都应通过 Next.js 的 `/api/*` 服务端路由转发调用。
- Google OAuth 回调地址只用于本地开发时配置在 Google Cloud Console：`http://localhost:3000/api/auth/callback/google`。
- 当前 Google 登录会创建或更新本地 `.data/auth-users.json` 用户记录，不保存 Google token；后续上线可替换为正式数据库用户表。
- OpenAI 接口当前使用 Responses API，便于统一处理图片输入、结构化输出和多步骤报告生成。

## 免费个人 API 用量标识

高德地图和和风天气当前按免费个人 Key 接入，用量不大，但产品里需要让调用边界可见：

- 设置页展示“免费 API 用量标识”，直接读取服务端本地累计；没有调用记录时显示 0 次，不用示例数字冒充真实用量。
- 设置页展示“API 接入清单”，明确 OpenAI 使用 Project API Key，高德使用“Web服务”Key，天气使用服务端 Key。
- 分析页展示“本次分析的数据源与额度护栏”，让用户在提交前知道截图识别、地图增强、天气舒适度和本地预检分别是否会消耗额度。
- 报告页展示“本报告的数据源与额度说明”，把 `dataQuality` 中的实时、缺输入、额度保护、请求失败和本地规则降级直接暴露给用户。
- 服务端每次调用高德或天气接口时，会写入一条轻量 usage 记录到 `.data/api-usage-events.json`。
- 统计口径先按产品侧自设阈值展示，例如本月 5,000 次地图调用、本月 1,000 次天气调用。
- 统计值不等同于第三方平台官方总额度，只用于避免个人免费 Key 被原型测试意外打爆。
- 接近阈值时，地图通勤可以降级为“用户手动输入通勤时间”，天气可以降级为“城市气候常识 + 明确提示未实时查询”。
- 片区初筛每次最多实时增强 3 个候选片区，避免一次提交触发过多高德调用。

建议后续增加的服务端表：

```sql
api_usage_events(
  id,
  provider,
  endpoint,
  feature,
  success,
  created_at
)
```

`/api/analyze/report` 的降级规则：

- 没有 `OPENAI_API_KEY`：使用本地规则生成报告。
- OpenAI 请求失败：使用本地规则生成报告，并在报告页显示降级提醒。
- 高德 Key 缺失或地址不完整：跳过实时通勤和 POI，报告会提示用户补充地址或手动核实。
- 天气 Key 缺失或请求失败：跳过实时天气，报告会按城市气候和居住偏好做保守提醒。
- 生活半径段落不会因为 POI 缺失而消失；没有实时周边数据时使用用户输入、偏好和保守默认值生成，并明确提示需要现场实测。

`/api/analyze/report` 的数据可信度：

- 服务端会在调用高德和天气前检查 Key、必要输入和产品侧用量阈值。
- 结果会保存 `dataSources` 和 `dataQuality`，历史报告、最新报告和导出 JSON 都能看到调用依据。
- `dataQuality.status=live` 表示本次拿到实时或增强数据。
- `fallback`、`missing_input`、`skipped_limit`、`failed` 表示已降级，并会把具体原因写入报告提醒。
- 高德和天气的额度保护基于 `.data/api-usage-events.json` 的本地累计，只用于原型阶段保护个人免费 Key。
- `/analyze` 页面在真正提交到 `/api/analyze/report` 前，会先做本地生成前预检，提示关键字段缺口、数据降级原因和看房必须核实项；这个预检不消耗 OpenAI、高德或天气额度。
- `/analyze` 的字段核对台只使用用户当前表单、截图识别返回值和本地预检结果，不新增外部调用；它用于提醒哪些字段来自截图、哪些是人工填写、哪些关键缺失。
- `/analyze` 页面会同时展示 API Guardrail，预估截图识别、报告生成、地图增强和天气舒适度各自的调用边界；缺少地址、工作地点或 Key 时，会在提交前说明本次会跳过哪些实时调用。
- `/analyze` 可通过 URL 接收 `source`、`reportId`、`reportContext`、`title`、`address`、`rent`、`city`、`workplace`、`budget`、`commuteLimit` 等上游字段；这些字段只用于预填和报告上下文，不会单独触发外部 API 调用。提交报告时，前端会把 `source`、`sourceReportId` 和 `reportContext` 传给 `/api/analyze/report`，服务端会将其纳入 OpenAI 输入或本地规则报告，并保存到本地历史档案。
- `/settings` 的应用行为设置会影响后续分析：报告深度会传入 `/api/analyze/report`，并同时影响 OpenAI 提示词和本地规则报告口径；关闭“截图结构化识别”后，分析页不会调用 `/api/analyze/extract`；关闭地图或天气实时数据后，`/api/analyze/report` 会跳过对应外部调用并把降级原因写入 `dataQuality`；关闭“官方核验入口提示”后，报告生成不会额外插入官方入口引导，但基础合同、授权、押金和付款风险仍会保留；开启“个性化优化”后，报告会按长期居住偏好强化最终建议、合同风险和看房清单；开启“自动隐藏敏感信息”后，报告页会默认隐藏手机号、邮箱、门牌号和房间号；关闭“本地优先保存历史”后，报告不会写入 `.data/reports.json`，但会保留在当前浏览器会话供 `/report/latest` 临时展示。
- 提交报告时，前端会把 `analysisPreflight` 一起传给 `/api/analyze/report`。服务端会把它保存进历史报告、导出 JSON 和报告页可信度面板，并把关键降级说明写入 `warnings`。
- 报告页会复用 API Guardrail 展示本报告的 `dataQuality`，同时读取对应居住决策档案生成 `nextBestAction`、完成标准、停止线和付款/签约闸门；报告页也会把当前城市、房源、租金、`reportId` 和 `reportContext` 继续带入片区初筛、通勤真实成本和生活半径审查，先复核风险是否来自上游取舍；通勤真实成本和生活半径结果会作为签前上游复核项参与判断，报告已触发风险且未通过时不会显示可付款或可签约；看房清单、官方核验、证据档案、付款闸门，以及复制或下载 Markdown 决策摘要当前不会自动消耗外部 API。
- 报告页的签前沟通包只根据当前报告、决策档案和本地模板生成补材料、暂停付款、约复看和合同确认文本，不调用外部模型，不读取微信、邮箱、支付账户或私人聊天记录。

`/api/analyze/report` 的生活半径输入：

- 前端可选传入目标生活半径、买菜、餐饮、药店、医疗、快递、洗衣、运动、公园、夜间补给、夜间照明、噪音源、生活方式和备注。
- 如果用户填写这些字段，本地规则和 OpenAI 提示都会优先使用用户主动输入。
- 如果用户没有填写，报告会结合高德周边 POI、居住偏好和保守默认值生成生活半径段落。
- 这部分只做“长期是否顺手”的决策辅助，不声称周边实时营业状态一定准确。

`/api/visit/checklist` 的报告/片区带入：

- 报告页点击“生成核验清单”时，会把通勤、生活半径、舒适度和合同风险压缩成 `reportContext`。
- 片区卡片点击“生成看房清单”时，会把片区名称、通勤判断、生活半径、风险、现场核实重点和停看规则压缩成 `reportContext`。
- 看房页通过 URL 接收 `reportContext`、房源标题、地址、通勤和偏好，并自动调用 `/api/visit/checklist` 生成现场任务。
- 服务端规则会把 `reportContext` 纳入描述判断，例如片区停看规则、通勤复跑、买菜、药店、快递、夜间照明、噪音、潮湿、授权和押金风险。
- 看房结果页会把停签信号、必须问清的问题和证据留存包压缩成新的 `reportContext`，继续带入 `/evidence` 和 `/payment`。
- 这个链路不消耗地图、天气或 OpenAI 额度；它只把已生成的片区/报告风险转成现场核验动作。

签约前工具的报告带入：

- 报告页的“官方核验”会带入房源标题、城市、地址、出租方类型、合同状态和 `reportContext`，并自动调用 `/api/official/verification` 生成官方核验计划。
- 报告页的“证据档案”会把授权、押金、维修、付款和交割风险压缩成 `reportContext`，并自动调用 `/api/evidence/pack` 生成留证计划。
- 报告页的“付款闸门”会带入房源标题、月租、拟定金、合同状态、授权状态、收款主体和 `reportContext`，并自动调用 `/api/payment/gate` 生成付款阻断项。
- 报告页的“签约风控”只预填风险底稿，不自动调用 `/api/contract/check`，避免用户打开页面就消耗 OpenAI 额度；用户需要粘贴真实合同或聊天记录后手动审查。
- 官方核验、证据档案和付款闸门当前都是本地规则，不消耗外部 API；合同风控在配置 `OPENAI_API_KEY` 后会优先走 OpenAI，失败或无 key 时降级为本地规则。
- 官方核验结果页会继续生成带参入口，把红旗提醒同步到 `/evidence` 和 `/payment`；携带 `reportId` 时，用户逐项确认高优先级官方核验后可把硬门槛状态写回居住决策档案。报告页和决策档案会把“生成核验计划”视为待复核，只有“官方核验硬门槛确认”通过才算官方核验闭环。
- 证据档案结果页会继续生成带参入口，把缺证提醒、付款备注和档案上下文同步到 `/payment`；付款闸门会把 `from=evidence` 标记为“已从证据档案带入”。

`/api/area/screen` 的降级规则：

- 没有 `AMAP_WEB_SERVICE_KEY`：使用本地片区规则估算租金、通勤和风险。
- 高德地理编码失败：返回本地规则结果，并提示用户补充更明确的工作地点或片区名。
- 候选片区超过 3 个：只对前 3 个做高德实时增强，其余建议分批提交。
- 高德调用只发生在用户点击“生成片区初筛”之后，页面初始渲染不会消耗额度。
- 无论使用高德增强还是本地规则，结果都会生成 `viewingQueue`，把片区分成优先看、备选观察和暂缓看房，并为每个片区返回现场核实重点和停看规则。
- 前端会基于 `viewingQueue` 和片区结果生成可复制片区看房排程包；这个文本整理不额外调用 OpenAI、地图或天气 API。
- 页面携带 `reportId` 时，前端会把片区初筛的优先看、备选、暂缓、第一片区、摘要和下一步动作以 `type=area` 写回 `/api/case-events`；这一步用于保存上游筛选证据，不额外消耗地图、天气或 OpenAI 额度。

所有第三方调用都只发生在服务端，前端不会拿到真实 API Key。

## 决策计划数据流

`/plan` 只使用用户主动输入。配置 `OPENAI_API_KEY` 后，会先生成一份本地规则基线，再调用 OpenAI Responses API 做智能任务编排；未配置 Key、请求失败或输出不完整时，自动回落到本地规则：

- 用户输入当前阶段、候选房源、决策天数、税后收入、预算、目标租金、通勤、居住方式、付款压力、合同状态和证据状态；普通进入时，这些默认值来自浏览器本地的决策画像。
- `/api/plan/build` 输出推进安全评分、可以推进/先补证/暂停推进、必须先做的任务、阻断项、今日行动包、暂停线、完成标准和建议进入的工具。
- 前端会把 `todayPlan`、`stopLine`、`doneDefinition`、证据清单和对外话术整理成可复制行动包；这个整理不额外调用 OpenAI、地图或天气 API。
- `/plan` 会读取浏览器本地决策画像做普通进入的默认值，也会读取 `/api/reports` 的最近报告摘要和 `inputSummary`；用户可选择一套房源，自动预填城市、房源标题、租金、预算、通勤上限和报告结论，并把本次行动包以 `type=plan` 写入 `/api/case-events`。若选择“暂不写回”，页面只生成计划，不写入档案事件。
- `/plan?reportId=...` 只使用本地报告存储做预填，不会在页面打开时调用 OpenAI、高德或天气 API。
- 计划结果会把现金流、证据档案、官方核验、付款闸门、签约风控、看房核验、独居安全和合租边界按优先级串起来。
- OpenAI 只接收用户在表单中主动输入的阶段、预算、通勤、付款、合同、证据和风险关注点，以及服务端生成的本地规则基线；不读取私人账号或后台数据。
- 返回结果会被服务端规范化到固定结构和允许跳转的工具路径，避免模型生成不可用入口。
- 不读取私人账号、微信、邮箱或租房平台后台数据。

## 居住决策档案事件流

`/case` 不是收藏夹，而是报告后的推进状态台：

- `/api/case-events` 使用本地 `.data/case-events.json` 保存工具结果摘要；`type=plan` 表示从决策计划页写回的今日行动包，`type=area` 表示从片区初筛页写回的看房队列和片区判断。
- 从报告页或 `/case` 进入 `/city`、`/commute`、`/life`、`/buy`、`/visit`、`/official`、`/evidence`、`/payment`、`/contract`、`/safety`、`/shared`、`/move`、`/handover`、`/repair`、`/renewal`、`/deposit` 时，会携带 `reportId`。
- 这些页面的侧边或底部“继续下一步”入口也会继续传递 `reportId`、城市、房源标题、租金/押金、阶段背景和压缩后的 `reportContext`；完整报告仍以 `reportId` 为准回看，URL 只承接短风险摘要，不新增外部 API 调用。
- 这些工具生成结果后，会写回事件类型、状态、摘要和关键提醒。
- `/case` 会把事件聚合到对应报告下，显示已完成动作、最新提醒、仍需处理的签前阻断项、签后生命周期下一步和当前 `nextBestAction`；从 `/plan` 写回的行动包会作为“决策计划”事件显示。
- `/case?reportId=...` 会从本地报告中聚焦当前房源，展示“当前报告已带入”、前置该房源并高亮；这只使用 URL 参数、本地报告和本地事件，不新增外部 API 调用。
- `/dashboard` 和 `/case` 的当前行动队列完全由本地报告、报告可信度和 `/api/case-events` 推导，按阻断风险、低置信字段、付款/签约状态和签后争议风险排序，不额外调用外部 API；`type=plan` 会进入工作台的计划覆盖指标和最新决策计划提醒。
- `nextBestAction` 是前端从报告结论、报告可信度、签前闸门、专项风险闸门、官方核验硬门槛、证据/付款/合同状态和签后生命周期中推导出的唯一优先事项；当入住现金流、交割、维修、续租或押金事件已写回阻断/待补证时，会优先处理这些签后现金和证据风险，再回到签前清单；它包含目的、完成标准、停止线和跳转入口。
- 档案行动包会根据 `nextBestAction` 的入口切换沟通文本：签前补材料、首笔支出、入住交割、维修垫付、续租涨租和退租押金分别生成不同的可复制话术，避免签后争议仍显示签约前补材料口吻。
- 报告页会读取同一批 `/api/case-events` 事件，把当前唯一优先事项放在报告头部，并提供上游取舍复核入口，把当前报告继续带到片区初筛、通勤真实成本和生活半径审查；再把看房核验、官方核验、证据档案、付款闸门、签约风控，以及按报告风险触发的独居安全/合租边界闸门渲染成“签前闭环进度”，并把入住现金流、入住交割、维修责任、续租涨租和押金回收渲染成“居住生命周期进度”。
- `/report/latest` 会优先读取本地原型报告存储中的最新一条，和 `/report/{id}` 一样接入 `nextBestAction` 与付款/签约闸门；如果用户关闭“本地优先保存历史”导致报告未写入 `.data/reports.json`，页面会从当前浏览器 session 的 `zhunaar:last-report` 读取临时报告兜底，并明确提示它没有写入居住决策档案。
- 同一事件表也承接上游择城、片区初筛、通勤真实成本、生活半径审查、买房压力测试和签约后的居住生命周期：城市账本、片区初筛、通勤真实成本、生活半径审查、买房压力测试、入住现金流、入住交割、维修责任、续租涨租和押金回收工具在携带 `reportId` 时会写回结果摘要；生命周期事件的 highlights 会携带关键金额、结论和证据字段，例如首笔支出、签后剩余现金、交割结论、维修预估费用、续租上限、押金目标返还、争议扣款和返还截止日；这些工具之间的结果跳转和侧栏入口会继续携带同一个 `reportId`、城市、房源、租金/押金、维修或扣款背景和短报告上下文，完整报告内容不重复写入每个 URL，报告页、工作台和居住决策档案可持续追踪同一条决策链的证据状态。
- `/api/reports/export` 会把 `.data/reports.json` 和 `.data/case-events.json` 合并为一份服务端决策档案 JSON；设置页的“完整本地数据导出”会在浏览器里继续合并 `zhunaar:user-preferences`、`zhunaar:app-settings`、首访状态和临时报告，且不会导出 `.env.local` 中的 API Key。
- 报告页的 Markdown 摘要复制/下载只使用当前报告、预检和决策档案状态在浏览器内生成，适合用户分享、看房和签前留痕，不调用外部接口；清空会同步清掉报告和事件，设置页还会清掉浏览器画像、应用设置和临时报告，并即时刷新设置页与导航摘要，避免历史报告删除后还残留签前闸门或签后生命周期状态。
- V1 只保存结构化摘要，不保存上传截图、合同原图或证据原件。

## 通勤真实成本数据流

`/commute` 只在用户点击生成后尝试高德路线增强；无 Key、设置页关闭地图实时数据、额度保护、地址不清或请求失败时，会自动回落到用户手动输入：

- 用户输入城市、候选房源、工作地点、税后收入、月租、单程通勤、步行到站、换乘次数、单程交通费、每月晚归次数和坏天气天数。
- 配置 `AMAP_WEB_SERVICE_KEY` 且设置页允许地图实时数据时，`/api/commute/cost` 会先对候选房源/小区和工作地点做高德地理编码，再查询公交/地铁路线；拿到结果后会覆盖单程分钟、步行距离、换乘次数和单程票价。
- `/api/commute/cost` 计算每月通勤小时、年度折算天数、直接交通费、晚归打车费、按收入折算的时间机会成本和真实月成本。
- `/commute` 支持接收片区初筛、房源体检或决策档案传入的城市、房源、工作地点、租金、通勤上限和 `reportContext`；页面携带 `reportId` 时，会把通勤结论、评分、真实月成本、阻断项和下一步动作写回 `/api/case-events`，并继续分流到片区初筛、多房源对比或房源体检；报告或档案再次读取该事件时，会更新签前闸门中的“通勤成本”状态。
- 用户可输入一个近通勤替代房的单程时间和月租，系统会估算“为了节省通勤最多值得多付多少租金”。
- 输出通勤可接受/谨慎接受/不建议长期住、通勤阻断项、现场实测清单、谈判杠杆和下一步动作。
- 结果会返回 `routeEvidence` 和 `dataQuality`，说明本次采用高德路线还是手动参数，以及未调用或降级的原因。

## 生活半径审查数据流

`/life` 只在用户点击生成后尝试高德周边 POI 增强；无 Key、设置页关闭地图实时数据、额度保护、地址不清或请求失败时，会自动回落到用户手动输入：

- 用户输入城市、候选房源、目标生活半径、买菜、餐饮、药店、医疗、快递、洗衣、运动、公园、夜间补给、夜间照明、噪音源和生活方式。
- 配置 `AMAP_WEB_SERVICE_KEY` 且设置页允许地图实时数据时，`/api/life/radius` 会先解析候选房源/小区位置，再查询 1.5 公里内的超市/菜场、餐饮、药店、医疗、快递、洗衣、运动和公园 POI；拿到结果后会辅助更新最近距离和配套数量。
- `/api/life/radius` 输出生活半径友好/需要取舍/不适合长期住、长期好住评分、核心短板、生活配套拆解、现场实测清单和谈判杠杆。
- `/life` 支持接收片区初筛、房源体检或决策档案传入的城市、房源和 `reportContext`；页面携带 `reportId` 时，会把生活半径结论、评分、核心短板、阻断项和下一步动作写回 `/api/case-events`，并继续分流到看房核验、片区初筛或房源体检；报告或档案再次读取该事件时，会更新签前闸门中的“生活半径”状态。
- 结果会重点检查工作日晚上、周末、生病、晚归和独居场景，不把“地图上很多点”误当成真正好住。
- 结果会返回 `poiEvidence` 和 `dataQuality`，说明本次采用高德 POI 还是手动参数，以及未调用或降级的原因。
- 不爬取贝壳、链家、自如、安居客等租房平台数据。

## 看房现场核验数据流

`/visit` 当前不消耗外部 API 额度，用本地规则把经验清单转成现场任务：

- 用户输入房源标题、城市、位置、楼层、楼龄、朝向、月租、通勤描述和居住偏好。
- `/api/visit/checklist` 按低楼层、老小区、北向、临街、独居、养宠、做饭等场景生成任务。
- 如果从 `/area` 带入片区上下文，会先输出“片区到房源验证”分组，复核通勤、夜间最后一公里、生活半径和停看规则。
- 输出按片区验证、房屋质量、居住舒适度、安全与动线、生活半径、签约材料分组的核验清单。
- 每个任务包含优先级、何时检查、怎么测、通过标准和留证方式。
- 同时输出必须问清的问题、证据留存包、停签信号和下一步动作。
- 前端会基于本地结果生成可复制现场核验包，把高优先级现场任务、必须问清的问题、证据留存和暂停定金/签约信号整理成可发送文本；该文本不调用外部模型，也不上传现场照片。
- 结果页可把停签信号、必须问清的问题和证据留存包继续带入证据档案或付款闸门；该跳转只复用本地生成结果，不新增外部 API 消耗。

## 证据档案数据流

`/evidence` 当前不消耗外部 API 额度，用本地规则把签约前后容易缺失的证据转成留存计划：

- 用户输入当前阶段、房源标题、城市、地址、出租方类型、押金付款方式和担心的风险。
- `/api/evidence/pack` 按二房东/转租、押金、维修、老小区、付款方式等风险生成证据任务。
- 输出身份与授权、房屋状态、付款与押金、沟通记录四组证据清单。
- 同时输出留证时间线、付款备注建议、补证提醒、最低证据门槛和可复制文本。
- 用户勾选高优先级证据后，如果页面携带 `reportId`，可以把当前完成度写回 `/api/case-events`，让 `/case` 和报告页更新证据闸门状态。
- V1 不上传、不托管证据原件，用户自行保存照片、视频、聊天记录和付款凭证。

## 独居安全审查数据流

`/safety` 当前不消耗外部 API 额度，只用用户主动输入生成安全核验任务：

- 用户输入城市、房源、楼层、门禁、楼道照明、电梯、晚归时间、最后一公里、快递外卖、室友/房东接触和担忧点。
- `/api/safety/audit` 按低楼层、门禁松散、楼道偏暗、夜路、晚归、快递外卖送门口、陌生合租和维修上门等场景生成安全任务。
- 输出独居安全评分、高风险红旗、夜间路线动作、隐私边界、必须问清问题和下一步动作。
- 前端会基于本地结果生成可复制独居安全核验包，把晚归路线、门禁楼道、钥匙换锁、维修上门、快递外卖和隐私边界整理成可发送文本；该文本不调用外部模型，也不读取实时定位或聊天记录。

- `/api/contract/check` 优先调用 OpenAI 识别长文本和截图风险。
- 没有 OpenAI Key 或请求失败时，使用本地规则识别高频风险表达。
- 输出包括：综合风险、风险项、证据、行动建议、沟通话术、缺失条款、看房交割证据清单和签字前整改项。
- 前端会把风险项与缺失条款合并为签字前整改清单，并在本地生成可复制整改沟通包，要求对方把风险条款改进到合同、补充协议、附件或可留存聊天确认里。
- 用户逐项确认后，如果页面携带 `reportId`，可以把整改状态写回 `/api/case-events`。
- 合同结果页会把综合结论、风险项、缺失条款、证据清单和下一步动作压缩成 `reportContext`，继续带入 `/evidence` 和 `/payment`；这两个跳转不会再次调用 OpenAI。
- 结果仅作为签约前风险提示，不替代律师意见。

当前风控依据来源：

- 市场监管总局《城镇房屋租赁合同（示范文本）》（2025 版）
- 市场监管总局关于发布《城镇房屋租赁合同（示范文本）》的说明
- 司法部关于国务院公布《住房租赁条例》的公开信息

## 多房源对比数据流

`/compare` 优先读取本地报告历史：

- 历史报告数量大于等于 2：读取 `.data/reports.json` 和 `.data/case-events.json`，按结论状态、真实月成本、通勤差额、综合评分、签前闸门状态和工具回写状态生成真实对比表。
- 历史报告数量等于 1：保留这一份真实报告并高亮当前关注房源，同时补入示例替代方案解释对比模型；示例替代不写入本地历史，不参与真实报告排序。
- 历史报告数量等于 0：展示明确示例状态，并用示例数据解释对比模型。
- 对比表中的房源名称可以打开对应 `/report/{id}` 完整报告。
- 工具回写存在时，对比表会补充签前闭环进度、可否付款、可否签约、当前阻断项和下一步工具入口。
- 从报告、决策档案或续租工具进入 `/compare` 时，页面会读取 URL 中的 `reportId`、`from` 和当前房源标题，只用于展示当前关注房源和高亮表格行；真实排序仍由报告结论、成本、通勤、可信度和闸门状态决定，不新增外部 API 调用。
- 混合对比中的“下一套真实候选”模板会生成 `/analyze?from=compare...` 链接，把低月成本、短通勤或低签约风险方向、当前房源取舍和核验重点写入 `reportContext`；这只是 URL 预填，不抓取房源平台数据，也不会在打开分析页时消耗 OpenAI、地图或天气额度。
- 前端会额外生成省钱优先、通勤优先、签前安全和先处理四个决策视角，帮助用户理解排名背后的真实取舍。
- 对比决策备忘录完全由当前页面已加载的报告和闸门数据在前端生成，只用于复制文本，不读取聊天、社交、支付或任何私人账号数据。
- 本地原型存储路径为 `.data/reports.json`，该目录已加入 `.gitignore`。
