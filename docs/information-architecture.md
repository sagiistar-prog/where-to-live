# 住哪儿 AI：当前信息架构

## 产品边界

住哪儿 AI 不做房源分发，不抓取房源平台，也不替代法律、金融或中介服务。产品只处理用户主动输入的信息，把生活成本、片区、房源、付款、签约和入住退租问题整理成可保存、可复核的判断。

## 主入口

1. 首页：一句话输入当前问题，系统识别是生活成本、房源体检、付款咨询、买房初判还是当前行动。
2. 工作台：查看最近启动的判断、当前房源记录、最近报告和下一步操作。
3. 生活成本：输入城市、收入、租金预算、通勤上限和储蓄目标，判断长期承受力。
4. 房源体检：输入房源位置、月租、工作地和主要顾虑，判断是否继续看房或继续谈。
5. 付款咨询：输入担心的合同及其他法律风险，确认是否应暂停付款、补材料或继续推进。
6. 当前行动：用户不知道从哪里开始时，先整理阶段、风险和今天最该处理的动作。
7. 方案与额度：展示免费、Pro、Max 三档方案，按使用频率解释额度。
8. 个人设置：保存常用城市、工作地、预算、通勤上限和账号信息。

## 用户主流程

### 换城市或换工作

用户输入候选城市、税后收入、租金预算和通勤上限。系统输出真实月成本、储蓄率、租金上限、可继续比较的城市和下一步建议。

### 看片区

用户输入城市、工作地、预算、候选片区和通勤上限。系统输出优先看、可备选、暂不考虑的片区，并说明通勤、租金和生活配套原因。

### 看具体房源

用户输入月租、位置、工作地、房源描述和担心的问题。系统输出房源体检报告，包含结论、主要风险、信息完整度、下一步和可保存记录。

### 付款前

用户输入担心的合同及其他法律风险。系统先判断是否建议付款，再列出需确认的问题、付款备注、收据要求和可复制沟通文本。

### 买房前

买房初判复用生活成本页，额外输入首付、月供和房价。系统判断长期现金流、月供压力和片区承受力，避免再做独立复杂页面。

## 保留原则

只保留用户在关键决策前需要看到的页面。内部服务、API Key、模型降级、外部数据调用策略、成本控制和商业化实现细节不进入用户页面。

页面和卡片保留前必须满足三个条件：

1. 用户能立即理解它解决什么问题。
2. 删除后会影响当前决策。
3. 输出能进入工作台、报告或下一步行动。

## 暂不作为主入口的能力

通勤成本、生活半径、官方查询、材料清单、合同确认、入住预算、交割确认、维修责任、续租判断和押金退还仍可作为深层工具保留，但不作为首页和主导航的第一层入口。它们只在报告、当前行动或具体风险触发时出现。

## 交付验收重点

1. 首页必须直接进入真实任务，不做营销式空转。
2. 工作台必须能让用户继续最近判断。
3. 生活成本、房源体检、付款咨询和当前行动必须可独立完成一次判断。
4. 登录注册必须支持电子邮件、图形验证码和邮箱验证码；Resend 未配置时可走本地演示码。
5. 报告必须先给结论，再解释原因，再给下一步。
6. 所有页面不得展示内部商业秘密、API Key 配置、服务成本策略或不必要的技术流程。
