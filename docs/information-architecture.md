# 住哪儿 AI 信息架构

## 产品北极星

帮助中国年轻人用更低认知成本做出更少后悔的居住决策。

## 核心用户

- 刚毕业或入职 1-5 年的年轻租客
- 正在换城市、换工作、换片区的人
- 第一次独居或女生独居用户
- 正在租售之间犹豫的年轻家庭或情侣
- 即将签约、担心合同和押金风险的人
- 被催先交定金、意向金、服务费或押金，但材料还没补齐的人

## 一级导航

顶部导航只保留高频决策入口，避免把完整工具链平铺成菜单墙：

1. 工作台 `/dashboard`
2. 决策计划 `/plan`
3. 居住决策档案 `/case`
4. 房源体检 `/analyze`
5. 签前闭环 `/visit`
6. 居住周期 `/move`
7. 多房源对比 `/compare`
8. 知识库 `/knowledge`

侧边导航按真实流程分组：

- 决策中枢：工作台、决策计划、决策档案。
- 择城与片区：城市账本、片区初筛、通勤成本、生活半径。
- 房源判断：房源体检、多房源对比、看房核验、独居安全、合租边界。
- 签前闸门：官方核验、证据档案、付款闸门、签约风控。
- 入住后：入住现金流、入住交割、维修责任、续租涨租、押金回收。
- 长期选择：买房压力测试、知识库、个人设置。

移动端导航使用同一套分组，但以阶段菜单呈现：每个入口必须显示一句“这个工具解决什么”，保证用户在通勤、看房现场、付款前等窄屏场景也能找到完整工具链。

首访画像 `/onboarding` 不放入常驻导航，而是作为登录页和工作台的引导入口：用于保存默认城市、工作地、收入预算、通勤上限、固定支出和居住偏好，后续 `/city`、`/area`、`/commute`、`/life` 和 `/analyze` 自动复用。桌面侧边栏与移动阶段菜单要显示当前画像摘要；未建立画像时，引导用户先完成画像，而不是继续展示固定示例城市。

## 用户旅程

### 旅程 -1：我第一次使用，不想每次都重复填

入口：登录后工作台提示或 `/onboarding`

路径：

1. 输入默认城市、工作地点、税后收入、预算区间、固定支出和通勤上限
2. 选择独居、养宠、做饭、近地铁、怕吵、怕潮湿、是否接受老小区等偏好
3. 保存到浏览器本地
4. 进入城市账本、片区初筛、通勤成本、生活半径或房源体检时，自动带入画像信息
5. 后续报告风险权重、默认预算、通勤上限和居住偏好复用同一套判断尺

### 旅程 0：我不知道现在该先做什么

入口：决策计划

路径：

1. 输入当前阶段、剩余决策时间、预算、目标租金、通勤和居住方式
2. 标记是否被催付款、是否已看到合同、证据是否补齐
3. 输出推进安全评分、阻断项和分阶段任务
4. 生成可复制今日行动包，明确今天只做什么、哪里必须暂停、做到什么才算完成
5. 选择已有房源报告，把今日行动包写回同一套房的居住决策档案
6. 按任务跳转到房源体检、证据档案、官方核验、付款闸门、签约风控或看房核验

工作台同步提供轻量下一步决策台：

1. 用户先选择看房前、看房后、被催付款、拿钥匙、入住后、续租退租或租售选择
2. 页面直接给出当前判断、暂停条件、证据清单和下一步最佳动作
3. 下一步最佳动作必须包含：目的、完成标准、停止线和跳转入口
4. 高风险场景优先暴露现金、证据和维修责任问题，避免用户被催着跳步骤

工作台同时提供居住生命周期总控：

1. 把付款前闸门、入住现金流、入住交割、维修责任、续租涨租和退租押金回收排成一条真实损失链
2. 每个阶段说明钱会亏在哪、现在该做什么、要保留什么证据以及输出什么判断
3. 明确交割证据会继续服务于维修责任和押金回收，避免工具之间互相孤立

工作台还要展示专项风险复核：

1. 针对独居、晚归、低楼层、合租、养宠、怕吵等用户画像触发独居安全或合租边界入口
2. 已完成复核时展示建议租、谨慎考虑或不建议租状态，并把红旗放进下一步动作
3. 未完成复核时保留跳转入口，不要求用户重复录入房源、城市、租金和偏好

居住决策档案承接已生成报告：

1. 每套候选房源都有一个推进状态，而不是孤立报告
2. 展示证据缺口、数据缺口、付款阻断项和下一步最佳动作
3. 下一步最佳动作说明先做什么、为什么做、做到什么程度、未完成前不能做什么
4. 继续追踪入住现金流、入住交割、维修责任、续租涨租和押金回收
5. 展示独居安全与合租边界专项复核状态，让报告后的细分风险有明确归宿
6. 高风险候选房源优先显示“先别付款”和补证动作
7. 不做平台式收藏夹，不展示房源流

### 旅程 A：我有一个 offer，不知道去不去

入口：城市账本

路径：

1. 输入候选城市和 offer
2. 输入税后收入、固定支出、储蓄目标
3. 比较房租、通勤、生活成本、真实月成本和储蓄率
4. 输出达标税后收入、安全租金上限、谈薪差额和降租差额
5. 判断当前 offer 是可进入片区、需要谈薪或降租，还是先别贸然换城
6. 复制择城 Offer 决策备忘录，带走推荐城市、真实月成本、谈薪差额、降租底线和下一步动作
7. 进入片区初筛

### 旅程 B：我已经确定城市，要找住哪片

入口：片区初筛

路径：

1. 输入工作地点和通勤上限
2. 输入预算、生活偏好、安全偏好
3. 输出片区候选、风险解释和“优先看 / 备选 / 暂缓”的看房队列
4. 复制片区看房排程包，带走优先顺序、现场核验重点和停看规则
5. 按看房队列安排前 1-2 个片区，每个片区先找 1-2 套房源
6. 从片区卡片进入看房现场核验，先验证通勤、夜间动线、生活半径和停看规则
7. 对具体房源进入房源体检

### 旅程 B2：房租便宜，但通勤很远

入口：通勤成本

路径：

1. 输入单程通勤、步行到站、换乘次数、晚归次数和坏天气天数
2. 输入收入、当前租金和近通勤替代房租金
3. 计算每月通勤小时、直接现金成本、时间机会成本和真实月成本
4. 输出是否值得为近通勤多付租金，并进入片区初筛或多房源对比

### 旅程 B3：白天看着方便，住进去才发现不顺手

入口：生活半径

路径：

1. 输入买菜、餐饮、药店、医疗、快递、洗衣、运动、公园和夜间补给距离
2. 输入夜间照明、噪音气味源和自己的做饭/晚归/周末恢复方式
3. 输出生活半径评分、核心短板、阻断项和夜间实测清单
4. 根据结果回到片区初筛、生成看房核验，或加入多房源对比

### 旅程 C：我已经有候选房源截图

入口：房源体检

路径：

1. 上传房源截图或手动输入
2. 输入工作地点、收入、预算、通勤上限、偏好
3. 生成体检报告
4. 查看真实月成本、通勤、配套、舒适度、合同风险
5. 生成看房核验清单，并自动带入报告里的通勤、生活半径、舒适度和合同风险
6. 进入官方核验，确认出租权、备案入口、合同示范文本和公共服务材料底线
7. 生成证据档案和付款闸门，把报告与官方核验风险转成补证清单和付款阻断项
8. 如准备签约，进入签约风控，粘贴真实合同后审查押金、维修、退租和授权条款
9. 如果是独居、晚归或低楼层，进入独居安全审查
10. 进入官方核验或证据档案

### 旅程 D：我有好几套房，不知道选哪个

入口：多房源对比

路径：

1. 导入多个体检报告
2. 横向比较租金、真实月成本、通勤、风险、舒适度
3. 输出第一选择、备选和最需要处理的风险项
4. 输出推荐顺序和取舍解释

### 旅程 E：我第一次独居或经常晚归，担心安全

入口：独居安全

路径：

1. 输入楼层、门禁、楼道、电梯、晚归时间、最后一公里和快递外卖方式
2. 输入室友、房东、维修上门和隐私边界担忧
3. 生成独居安全评分、高风险红旗和现场核验任务
4. 输出可复制独居安全核验包；高风险未消除前暂停定金和签约，必要时回到片区或房源体检重选

### 旅程 F：我想合租，但担心室友和公共空间

入口：合租边界

路径：

1. 输入室友人数、房间类型、公共空间、清洁、访客、费用和押金责任
2. 核验签约主体、转租授权和收款主体
3. 生成合租边界评分、风险项、必须问清问题和合租约定条款
4. 复制合租边界确认包，把问题、条款、证据和暂停付款条件发给出租方、室友或中介确认
5. 高风险未写清前暂停付款，必要时回到多房源对比

### 旅程 G：我准备签合同了

入口：签约风控

路径：

1. 粘贴或上传合同条款
2. 识别押金、维修、提前退租、转租授权风险
3. 输出修改建议、签约前核验动作和签字前整改清单
4. 进入官方核验，确认备案、示范合同和出租权底线
5. 生成证据留存清单
6. 进入证据档案，补齐付款、授权、交割和聊天确认

### 旅程 H：我不知道该去哪里查官方信息

入口：官方核验

路径：

1. 输入城市、当前阶段、房源和担忧
2. 生成当地备案入口、示范合同对照和租赁底线清单
3. 核验出租权、备案路径、公共服务材料影响和付款主体
4. 将核验结果同步到证据档案

### 旅程 I：我被催先交钱，但材料还没补齐

入口：付款闸门

路径：

1. 输入付款类型、金额、合同状态、授权、收款主体和退款规则
2. 判断定金、意向金、押金、服务费或首笔租金是否可以先付
3. 输出付款阻断项、付款备注模板、收据要素、可复制暂停付款补证包和转账前硬闸门
4. 高风险未解除前回到官方核验、证据档案或签约风控

### 旅程 J：我准备付款了，但不确定现金够不够

入口：入住现金流

路径：

1. 输入收入、手头现金、月租、押付方式、中介费和搬家添置支出
2. 计算首笔支出、签后剩余现金和安全垫
3. 对比当前条件、谈付款周期、延后添置三种情景
4. 输出是否暂停付款、可复制现金流谈判包和下一步动作

### 旅程 K：我已经要付款或入住了，怕之后扯皮

入口：证据档案

路径：

1. 输入当前阶段、房源、出租方、押金和担心的风险
2. 生成最小可用证据包
3. 按身份授权、房屋状态、付款押金、沟通记录补齐证据
4. 输出付款备注、留证时间线、停签/补证提醒和付款/签约前最低证据门槛

### 旅程 L：我要拿钥匙入住了，怕退租时扯皮

入口：入住交割

路径：

1. 输入合同交割状态、钥匙门禁、表读数、家具家电、旧损坏和历史欠费
2. 生成交割可控评分、阻断项、交割任务和拍摄清单
3. 输出可复制的交割确认包，覆盖钥匙门禁、表读数、旧损坏、家具家电、历史欠费、费用边界和未确认前的暂停线
4. 交割结果可一键带入证据档案、维修责任、交割确认/历史欠费补付闸门和押金回收；后续维修、付款争议和退租都可反向引用

### 旅程 M：我住进去了，但维修责任说不清

入口：维修责任

路径：

1. 输入漏水、发霉、家电故障、门锁失效或旧损坏问题
2. 输入合同维修条款、发现时间、证据情况、出租方响应和预估费用
3. 输出责任倾向、报修证据、费用边界、可复制维修责任通知包和升级路径
4. 维修结果同步到证据档案；涉及退租扣款时带入押金回收；合同条款不清时进入签约风控

### 旅程 N：房东涨租，我不知道续不续

入口：续租涨租

路径：

1. 输入当前租金、续租报价、同片区替代租金、搬家成本、押金风险和通勤变化
2. 计算续租上限、搬家回本月数和三种方案 12 个月总成本
3. 输出可复制续租谈判包、续租补充协议清单和搬家准备清单
4. 决定续租则先带入签约风控审查续租补充协议，再带入付款闸门核对新租金、押金沿用或调整、付款周期和凭证；决定搬家则带入押金回收和多房源对比

### 旅程 O：我要退租了，担心押金被扣

入口：押金回收

路径：

1. 输入押金、退租日期、通知期、拟扣款和证据情况
2. 拆分明确费用和争议扣款
3. 生成退款目标、谈判底线和返还截止日
4. 输出交割留证清单、扣款依据请求话术和逾期升级动作
5. 押金争议证据可同步回证据档案；对方拒绝给依据或逾期不退时进入官方投诉/调解路径；被要求签扣款确认、放弃追偿或补付费用时进入付款/确认闸门；维修扣款可回到维修责任页拆解

### 旅程 P：我在想要不要买房

入口：买房压力测试

路径：

1. 输入家庭收入、首付、目标总价、贷款周期
2. 计算月供收入比、安全垫、持有成本
3. 比较继续租房、刚需上车、改善购房三种情景
4. 输出现金流风险和生活质量变化

## 页面职责

### 首页

职责：建立品牌定位和信任。强调“不卖房源，只做独立体检”，并让用户从高频真实痛点直接进入工具或首访决策路径。

核心模块：

- 城市航拍视频背景和沉浸式首屏
- 主标题
- 首屏决策输入：用户选择体检房源、被催付款、筛片区或排计划，输入一句当前情况后由 `/start` 抽取城市、租金、付款金额、工作地、预算、通勤上限、候选片区和阶段等关键信息；默认体检模式也会自动识别退押金、维修垫付、入住交割、续租涨租和首笔支出压力，预填进入对应工具
- CTA：查看示例报告；顶部和首访路径继续引导用户先建画像
- 首访四步路径：建画像、上传房源、看价值账本、过签前闸门
- 右侧 AI 报告预览卡，首屏直接展示评分、结论和关键风险
- 被催付款、入住交割、续租涨租、退租押金等紧急入口
- 三大价值点

### 工作台

职责：承载产品全貌、用户回访和当前最紧急的居住决策。

核心模块：

- 下一步决策台
- 当前行动队列：读取历史报告和工具回写，按阻断风险、低置信字段、付款/签约状态和签后争议风险排出最该先处理的 1-3 套房
- 计划覆盖指标：行动队列区显示已有多少套候选房源写回过决策计划，提醒用户哪些房源还缺当前行动包
- 当前最该处理：突出一套最需要暂停、补证或签前确认的候选房源
- 最新决策计划：读取 `type=plan` 的档案事件，在首屏展示暂停线、今日行动和完成标准；没有写回时引导进入 `/plan?reportId=...`
- 下一步最佳动作：目的、完成标准、停止线、行动入口
- 报告可信度摘要：展示低置信待补房源数量、当前重点房源的预检分数和补证重点
- 签前闸门摘要：闭环进度、可否付款、可否签约、当前阻断项

- 现场任务进度

- 必须问清的问题、证据留存包、停签信号和可复制现场核验包
- 结果分流：把现场停签信号、证据留存包和必须问清的问题继续带入证据档案和付款闸门

### 独居安全

### 合租边界

### 官方核验

- 下一步动作：暂停付款、补官方核验、生成付款补证档案或进入签约风控；跳到证据档案时必须携带付款金额、月租、合同状态、授权、收款主体、退款规则、收据凭证、催付压力和本次付款阻断项

- 结果分流：把首笔支出、现金流红旗、押付结构、中介费/服务费、收据要求和谈判杠杆继续带入付款闸门、证据档案、签约风控和交割验收

- 每条知识卡必须展示建议核验来源，避免用户误以为建议来自无法验证的“AI 常识”。
- 每条知识卡必须提供一个对应工具入口，不停留在泛泛阅读。
- 知识库承担“发现问题后马上行动”的轻量分流，不替代报告、决策档案和工具结果。
- 知识库不爬取租房平台，不复制非开放授权全文，不替代官方查询、律师意见、专业鉴定或调解结论。

职责：保存个性化判断上下文。

核心模块：

- 默认工作地点
- 税后收入、预算、通勤上限和固定支出
- 预算区间
- 通勤上限
- 居住偏好
- 本地保存并带入房源体检
- 模型设置
- 数据源设置

- OpenAI、高德 Web 服务、天气 Key 的服务端配置状态
- 高德和天气个人免费额度的产品侧用量标识
- 同一套 API Guardrail 会在 `/analyze` 和报告页复用，避免用户只在设置页才看见额度边界
- 报告数据来源、降级原因和工具回写事件会随决策档案导出
- 隐私设置
- 完整本地数据导出：设置页会把服务端报告/事件与当前浏览器里的决策画像、应用设置、首访状态和临时报告合并成一份 JSON；不导出 `.env.local` 的 API Key
- 本地档案清空：清空会同步移除报告历史、签前闸门事件、签后生命周期事件、浏览器画像、应用设置和临时报告，并让设置表单、应用开关和导航摘要即时回到默认态，但不删除服务端环境变量中的 API Key

实现状态：

- 个人偏好会写入浏览器本地，用于分析页、片区筛选、通勤、独居安全和合租边界默认值；桌面侧边栏和移动阶段菜单会读取同一份画像并即时刷新城市、工作地、预算和通勤摘要。
- 应用行为设置会写入浏览器本地；报告深度、截图结构化识别、地图实时数据、天气实时数据、官方核验入口提示、个性化优化和本地历史保存已参与分析流程，报告页敏感信息脱敏已参与展示流程。
- 关闭本地历史保存后，报告只保留在当前浏览器会话，`/report/latest` 会优先尝试读取临时报告兜底。
- 清空历史记录需要二次确认，避免误删报告、签前闸门、签后生命周期事件、画像和应用设置；清空成功后会广播画像和应用设置更新，当前页面不需要手动刷新。

## V1 成功标准

- 用户能在不知道先做什么时，1 分钟内得到当前阶段的任务顺序和必须暂停项。
- 用户能在换城市或接 offer 前看到税后收入、租金和储蓄目标之间的硬差额，而不是只看名义涨薪。
- 用户能在 3 分钟内输入一套房源并得到报告。
- 用户能把通勤分钟折算为月度时间、现金和租金取舍，而不是只看地图静态时间。
- 用户能看懂这套房为什么建议租、谨慎考虑或不建议租。
- 报告里必须有可执行动作，而不是泛泛建议。
- 报告后必须提供可复制沟通文本，让用户能向中介或房东补材料、暂停付款、约复看和确认合同条款。
- 多房源对比必须能解释取舍。
- 签约风控必须能指出押金、授权和维修责任风险。
- 付款闸门必须能在材料不齐时明确提示暂停付款，并给出可复制的付款备注和沟通话术。
- 入住交割必须能让用户知道拿钥匙当天该拍什么、确认什么、哪些缺口会影响退租押金。
- 维修责任必须能提示用户先报修、留证、确认费用边界，再决定是否垫付维修。
- 续租涨租必须能给出续租上限、搬家回本月数和可复制谈判话术。
- 押金回收必须能承接交割、维修和续租上下文，避免退租前重新组织材料。
- 产品整体必须体现不卖房源、不爬平台数据、站在用户侧。
