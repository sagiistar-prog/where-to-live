# 从找到资料到找到有用依据

用户在付款、签约或退租前，要确认适用于房屋所在地的规则。产品需要返回能核对的来源，也需要在没有实时行情、没有合同正文时清楚地停止。来源数量不等于任务完成率。

本轮使用 18 个公开官方来源、283 个片段和真实 BAAI/bge-small-zh-v1.5 模型，比较关键词、向量和混合检索。来源清单见 [sources.json](../knowledge/sources.json)，采集时间、正文长度及哈希见 [coverage](knowledge-source-coverage.json)。范围是全国及北上广深部分租赁政策，不覆盖全部城市和法规。

## 发现和取舍

初始 24 个开发案例包括 18 个有来源问题和 6 个不应给出证据的问题。原实现会因“广州”“可以”等词项命中无关段落；同一部较长法规也会占满前三个结果，挤掉更具体的当地资料。

改动包括：过滤常见无区分度词项；住房混合检索使用关键词与向量 2:1 的加权 RRF；向量和混合结果中同一来源最多占两条；网页、JSON 检索与 PostgreSQL 服务共用明确的能力边界规则。边界规则是有限的词项模式，不能视为完备的语义分类器。

| 指标 | 初始混合检索 | 修复后混合检索 | 修复后关键词 |
|---|---:|---:|---:|
| Hit@3，有来源的 18 题 | 17/18 | 18/18 | 18/18 |
| 平均来源 Recall@3 | 0.916667 | 0.972222 | 0.972222 |
| MRR@3 | 0.888889 | 0.962963 | 1.000000 |
| 平均来源精确率 | 0.638889 | 0.592593 | 0.740741 |
| 无答案 6 题输出证据 | 6/6 | 0/6 | 0/6 |
| 地区混入案例 | 0 | 0 | 0 |

保留 [修复前](evaluation/housing-baseline.json) 与 [修复后](evaluation/housing-release.json) 的逐题结果。来源精确率下降是实际代价：来源更分散也引入额外候选。混合方案没有在所有指标上胜出，2:1 权重仅是当前开发集上的工程取舍。

另增加 [8 个后续探针](../knowledge/evaluation/prospective.json)，包含 4 个不同问法和 4 个无答案问题。关键词 Hit@3 为 3/4，混合为 4/4，混合无答案输出为 0/4；[结果在此](evaluation/housing-probes.json)。这些题在修复后编写，既非盲测，也非独立用户样本。它们提示语义召回对改写问题可能有帮助，不能证明整体优于关键词。

## 如何复现

先按 [知识库说明](../knowledge/README.md) 收集并构建独立索引。网页变化会改变语料，所以报告始终记录语料和题集哈希。报告文件不允许覆盖。

```sh
python knowledge/evaluate.py --language zh --index output/public-kb/index.json --cases knowledge/evaluation/cases.json --output output/evaluation/run-1.json --cache-dir .cache/models --min-hit-rate 1 --max-false-evidence-rate 0
```

任一门槛失败或缺少对应分母时退出码为 2；结果仍保存，不能挑选成功结果覆盖失败记录。关键词模式不运行查询向量推理。模型回归 CI 使用仓库自带的 3 份原创虚构资料和 6 题，不依赖政府网页稳定性；公开来源评测单独运行，不能拿虚构样例成绩替代。

## 指标的含义

- Hit@k：前 k 个片段中是否出现标注的来源。
- Recall@k：找回的不同标注来源数除以该题全部标注来源数；重复片段不重复计分。
- MRR@k：第一个标注来源出现位置的倒数，未命中计 0。
- 来源精确率：返回的不同来源中，属于标注相关来源的比例；它不是 Ragas 的 context precision / average precision。
- 无答案输出率：明确不应输出证据的题目中，实际输出证据的比例。
- evidence_policy_accuracy：是否应该输出任何证据与实际状态相符；不是答案正确率。

标注是开发者对来源相关性的假设，可能不完整；命中来源不保证命中段落回答了问题。延迟仅衡量模型加载后的组件运行，包括语义模式的查询推理，不含网页、数据库或启动时间，也不是隔离硬件基准。

## 验证层次

本轮 22 项 Python 测试通过，包括 2 项真实 PostgreSQL 测试；8 项网页项目测试与生产构建通过。单独知识服务使用实际 BGE 和 pgvector，五个地区均未混入其他城市，实时行情问题返回无证据，过长输入返回 400，见 [服务记录](evaluation/housing-service.json)。283 个住房片段的实际 tokenizer 最大长度为 321，小于模型上限 512，见 [长度记录](evaluation/token-budget.json)。

默认网页的桌面和手机测试通过：查询、键盘提交、无依据提示、保留输入及模拟长度错误。axe 自动检查无命中，不等于全面无障碍认证，见 [网页记录](evaluation/housing-ui.json)。

独立界面复查发现边界规则误拦截了“房东说明年涨价，合同应该怎么约定？”和“未提供合同就要求交押金，需要先核对什么？”。收窄规则后，两题在默认网页和独立 pgvector 服务均返回来源，真正的价格预测与未提供合同的有效性判断仍不输出证据，见 [反例回归](evaluation/housing-scope-regression.json)。复查者将这一项修复评为 resolved / ship；该结论仅覆盖已提出的修复项。

带 HOUSING_KB_URL 的网页启动曾被自动审批拒绝，返回 `blocked by policy`，未给出更具体原因。本轮没有换路径重试；网页至完整向量服务的端到端验收仍未完成。没有真实试用参与者、律师审核、线上客户数据库或客户价值指标。

## 下一轮决策门槛

先补充独立标注的常见任务、同义问法、跨地区冲突和失效政策，再决定分词器、权重与重排模型。逐段证据相关性和未回答率必须与任务完成率一起观察；不能仅为了提高 Hit@3 增加结果数。来源有效期检查与定期更新仍需持续维护。
